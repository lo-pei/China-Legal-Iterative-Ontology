# ADR-0012 · 概念层首批导入（民法典概念骨架）

## 1. 背景

负责人 2026-11-10 投递两份整理件（`民法典法律概念释义` 166 条、`民法典主体名词清单` 298 条），指令为「加入」本体。该投递使两件事同时成立：

1. 概念层有了第一批内容来源，ESC-0002 所要求的「材料」部分到位——但材料形态是**整理件**，不是规范原文，也不是 `raw/authority/` 原件；
2. 该批材料覆盖整部民法典，与 `PLAN/01` §1 的「单一子领域深挖」前提不一致（ESC-0001 仍未裁定）。

现有元设计对这两点都没有承载：状态词表没有「投递材料」这一来源类型；`E-MOD-01` 假定任何概念都能归入五模块；tbox 指纹口径假定「阶段内零变化」，无法区分「概念层扩充」与「元模型漂移」。

## 2. 决策

### 2.1 新增溯源值 `law:溯源-投递材料`

- 定义：负责人投递的整理件（清单、释义、汇总表），非规范原文、非 `raw/authority/` 原件。
- 能力边界：**只能支撑 `判断状态=候选`，永远不得支撑 `已验证`**。要升 `已验证`，必须换成规范原文（走 ESC-0002 选项 A）或取得 `负责人裁定`。
- 与 `未溯源` 的区别：有明确投递人与文件指纹（PROV 登记），可进 Wiki 与 RAG 召回；`未溯源` 不进任何表示层。
- 与 `权威材料` 的区别：材料强度。整理件可能含学理归纳、可能漏条，故不得作确定答案。

### 2.2 概念层落点与生成方式

| 文件 | 性质 | 可手改 |
| :--- | :--- | :--- |
| `ontology/tbox/70-concept-metadata.ttl` | 概念层元数据词汇（条号、统计、分组、指纹） | 可（有 CON 时） |
| `ontology/tbox/71-concepts-civil-code.ttl` | 445 个概念类，**生成物** | **不可**，改规则表重跑 |
| `tools/import/import_civil_code.py` | 导入器（解析 → 合并 → 归类 → 输出） | 可 |
| `tools/import/module-assignment.tsv` | 模块归属审阅表（445 行，逐条含「依据」） | 生成物 |

选生成而非手写的理由：445 条手工录入不可复现、无法 diff 规则变更、且极易在条号上出错。生成式使「归类规则」成为唯一可审对象，TTL 只是规则的投影。

### 2.3 模块归属三规则（顺序适用）

1. **清单主体优先**：出现在《主体名词清单》中的词条归主体模块（该清单本身就是「谁」的枚举）。
2. **节默认 + 名称覆盖**：其余概念按所属编/节取默认模块；与定义句式冲突者按名称覆盖（28 条，逐条写在导入器 `NAME_OVERRIDE`）。
3. **待裁定**：两种归类都能自圆其说者不强行归属，标 `判断状态=待裁定` + `受裁定于 ESC-0004`。

配套的两条归类口径（写入导入器，可复审）：

- **义务归关系模块**：义务是法律关系的内容（「谁对谁负担什么」）。例外：义务为某主体制度固有内容者随该制度（如 `监护职责` → 主体模块）。
- **债之发生原因归关系模块**：合同、无因管理、不当得利、侵权虽含行为侧面，但其推理功能是请求权基础，故归关系模块；行为侧面由意思表示、事实行为概念承载。

### 2.4 能力问题锚定

统一锚 `CQ-M01`（五模块互斥且能覆盖首批概念）——本批正是 CQ-M01 的检验语料；另按模块加 1 个功能锚点：

| 模块 | 附加锚点 | 理由 |
| :--- | :--- | :--- |
| 主体模块 / 关系模块 / 效果模块 | `CQ-D01` | 定位请求权基础与效果时被检索 |
| 行为模块 | `CQ-D03` | 事实归入要件时作为行为类型 |
| 规范模块 | `CQ-D02` | 作为要件标注的规范侧槽位 |
| 待裁定 | 无 | 模块未定，不主张功能位 |

逐条精化留待子领域确定后（ESC-0001）做，不在本批伪造精确度。

### 2.5 `E-MOD-01` 的豁免口径

`E-MOD-01`（概念无模块归属=悬浮）增加一个窄豁免：**同时满足** `判断状态=待裁定` 且 `受裁定于` 非空时，不报悬浮。理由：模块归属本身已升级，强制归属等于替负责人裁定，正是 ESC 机制要防的事。豁免不降低门槛——`E-ESC-01` 仍要求对应 ESC 存在且为 `open`/`resolved`。

### 2.6 指纹口径修订（CQ-M05 的可测性）

原口径「tbox 指纹在阶段 2 内不变」在概念层扩充时必然失效，导致每次导入都触发一条无法消除的 `W-TBOX-DRIFT`。修订为：

- 指纹**按版本登记**（PROV 每次实质变更新增一条），不再要求「阶段内恒定」；
- 同时计算**概念层指纹**（`7*.ttl`）与全量指纹，写入校验报告与 PROV；
- 元模型（`00–60`）的变更须 ADR，概念层（`70+`）的变更须 CON——以文件号段区分变更类型；
- `W-TBOX-DRIFT` 的语义相应改为「未登记的结构性变更」，登记后即消失。

版本由 `0.1.0-bootstrap` 升为 `0.2.0-civil-code`。

### 2.7 修补元模型缺口：`law:模块 ⊑ law:法律概念`

导入时暴露一个自举轮未被发现的结构缺口：`10-module.ttl` 只声明了「模块 ⊑ 模块」，未声明「模块 ⊑ 法律概念」。于是「概念 → 模块 → 法律概念」这条类链是断的：

- 若不修补：任何从 `law:法律概念` 根类出发的检索（`tools/sync` 的概念块生成、`tools/vis` 的概念分区、`E-ANC-01` 的能力问题锚定检查）都只能看到直接挂 `法律概念` 的节点，**445 条概念中的 439 条会被静默漏掉**——不报错、不警告，只是不出现。这是最危险的一类缺陷。
- 修补方式：`law:模块 rdfs:subClassOf law:法律概念`。模块是概念分类树的分区节点，作为概念的下位类是标准分区模式。
- 连带修正：`E-MOD-01` 与 `E-ANC-01` 需排除模块类自身（分区节点不是待归类概念），否则 5 个模块会各自被判「悬浮」。已在 `validate.py` 的 `check_taxonomy` 与 `check_cq` 两处一致实现。

该修补属于**元模型变更**（`10-module.ttl`），按 §2.6 的口径须有 ADR，本小节即为该依据。

## 3. 理由

1. **不伪造确定性**：445 条全部 `候选 + 投递材料`，无一条 `已验证`。整理件的释义可能来自学理通说（投递件自述 12 条），若标 `已验证`，溯源链在第一次复核时就会断。
2. **不伪造模块归属**：五模块是法律概念分类轴，`期间`、`占有`、`不可抗力` 在现有五类下没有自圆其说的位置。强行塞进某一模块会让「模块归属」这一判断失去信息量，并使后续按模块检索产生系统性错误。
3. **可复现优于可读**：445 条由脚本生成，规则表可审、可改、可重跑；手工 TTL 在第二轮复核时无法回答「这条为什么在关系模块」。
4. **范围冲突显式化**：本批含人格权（11）、婚姻家庭（9）、继承（12）、知识产权（1）等 `PLAN/01` §1 排除项。把它们挡在概念层之外会得到一份残缺的检索骨架；放进来又会让范围冻结形同虚设。故采「概念层全量骨架 + 规则/案例层仍受 ESC-0001 约束」的双层处置，并在 §5 写明约束。

## 4. 放弃方案与代价

| 放弃方案 | 放弃原因 | 代价 |
| :--- | :--- | :--- |
| 把两份清单当 `权威材料`，直接标 `已验证` | 整理件非规范原文，含 12 条学理归纳；标 `已验证` 违反 §4.3 末句与 AGENTS 禁止事项 4 | 无（避免了溯源链污染） |
| 把 445 条做成 `owl:NamedIndividual` 而非类 | 实例无法承载 `rdfs:subClassOf 模块`，也无法通过 E-MOD-01/E-ANC-01，等于绕开元设计 | 无 |
| 只做 166 条有定义的概念，主体名词留在清单里 | 主体名词是请求权主体识别的检索入口，缺它则 311 条主体概念无 IRI 可引用 | 检索覆盖率下降约 2/3 |
| 全部强行归五模块，不设待裁定 | 会产出 6 条错误归属，且无人能发现（错误归属不触发任何校验） | 无 |
| 把 `70/71` 放进 `ontology/abox/` 以避开指纹变化 | 概念是类不是实例，放 abox 使「层」轴失真，且掩盖元模型变更 | 无 |

## 5. 生效约束

1. `71-concepts-civil-code.ttl` 不得手改，任何修正改 `import_civil_code.py` 的规则表后重跑，并更新 `module-assignment.tsv`。
2. 本批任何条目不得在未更换材料前升为 `已验证`；升格须附规范原文定位（条号 + 版本）与复核者。
3. 概念层收录**不改变** `PLAN/01` §1 的范围排除：人格权、身份法、知识产权、公司证券在**规则层与案例层**仍属排除项，ESC-0001 的裁定不受本批影响。
4. 待裁定 6 条不得被任何规则、要件、案例引用（进入确定性表示层的前提是模块归属确定）。
5. 新增溯源值的门禁语义同步写入 `SCHEMA.md` §5 与 `tools/sync/sync.py`；三者不一致视为工具缺陷。

## 6. 复审触发条件

1. 负责人对 ESC-0004 作出裁定 → 消费裁定，改写 6 条归属，重跑导入器，撤销本条 §2.5 的豁免必要性评估。
2. 任一概念的模块归属在复核中被改判 → 记录改判原因，若同类改判累计 ≥5 条，复审 `SECTION_MODULE` 节默认表。
3. 规范模块概念数长期 ≤1 → 复审「规范模块」是否实际承载元层规范类型而非民法典概念（可能是模块轴的定义问题，而非归类问题）。
4. 若 `raw/authority/` 到位并逐条核对释义 → 概念可升 `已验证`，届时本条 §2.1 的材料强度边界需重写。
