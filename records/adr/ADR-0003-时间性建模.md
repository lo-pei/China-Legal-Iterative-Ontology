# ADR-0003 · 时间性建模

## 1. 决策

采**双层时间模型**：

- 第一层 `law:抽象规范`：规范身份（同一「规范」跨修订保持同一身份），只携带稳定标识与规范名称。
- 第二层 `law:规范文本版本`：某一时点的文本表述，携带 `law:公布日期`、`law:生效日期`、`law:失效日期`（可空，空表示现行有效）、`law:文本`（指向 `raw/authority/` 的定位串）、`law:版本序号`。

规则（`law:规则`）**必须**挂到且仅挂到一个 `law:规范文本版本`（`law:隶属版本`）；规则本身不携带生效/失效日期，日期一律由版本承载并向上继承。

## 2. 理由

1. 同一规范不同时期的表述差异是真实存在的（修正、增补但书、改动数额标准）。若规则节点挂单一日期属性，则「2020 年版本的 A 条」与「2023 年版本的 A 条」只能是两条互不相关的规则，无法表达「同一规范身份、不同表述」，也无法回答「某案发生在 2021 年，应适用哪一表述」。
2. 双层使**时间与文本解耦**：废止条件（ADR-0004）指向版本，规则结构不变；若把日期放在规则上，每次修法都要重建规则节点，案例层引用的规则 IRI 会全部失效，历史案例的溯源性断裂。
3. 版本层是溯源的天然锚点：`law:文本` 字段登记原文定位（文件名 + 条号 + 字符区间），满足 §5.2 溯源链「标注值 → 源文本位置」的要求。

## 3. 放弃方案与代价

| 放弃方案 | 放弃原因 | 代价 |
| :--- | :--- | :--- |
| 规则节点挂单一 `生效日期/失效日期` 属性 | 同一规范不同时期表述差异无法表达；修法即重建节点 | 案例层引用会指向失效 IRI；需额外的「IRI 迁移表」补丁，违反「不在概念层打补丁」 |
| 以「时态化规则」（四维谓词，把时间作为关系参数） | 首版无推理机、以 SHACL 校验为主，四元组化会使校验与查询复杂度超出自建工具能力 | 可表达力更强但不可维护，且人类审阅者在 Wiki 上无法阅读 |

## 4. 生效约束

- `law:规范文本版本` 必须有 `law:生效日期` 与 `law:文本`；`law:失效日期` 可空。
- 同一 `law:抽象规范` 的版本不得出现生效区间重叠（`tools/validate` 报 E-VER-02）。
- 规则若需引用「制定时点」以外的时点（如溯及适用），用 `law:溯及条款` 单独标注，不得改写版本日期。
- 版本与日期的取值必须来自 `raw/authority/`；系统不得推定生效日期。

## 5. 复审触发条件

- 出现「同一规范在同一时点存在两个有效文本」（如不同公布主体）→ 复审是否需要「并行版本」概念。
- 若首批案例中 ≥20% 涉及法的时间效力争议（旧法适用、溯及力）→ 复审是否把时间效力争议升为独立争点类型。
