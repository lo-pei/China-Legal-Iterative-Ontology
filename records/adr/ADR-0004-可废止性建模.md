# ADR-0004 · 可废止性建模

## 1. 决策

在规则层引入独立类 `law:废止条件`，并允许废止条件作为**独立节点**存在（不只挂在被废止规则上）：

- `law:废止类型`：`后法废止` / `上位法废止` / `特别法优先` / `目的性限缩` / `约定排除` / `要件不成立`（六类，可扩展需 CON+ADR）
- `law:废止对象`：被废止或受限制的规则 / 规范文本版本 / 构成要件
- `law:废止生效日`（必须）
- `law:优先规则`（可空；表达「特别法优于一般法」「新法优于旧法」之外的裁判规则）
- `law:废止理由定位`（指向权威材料或案例说理的溯源串）

规则通过 `law:废止条件` 反向或正向关联；同时保留 `law:受废止于` 反向属性以便查询。

**明确不采用**：规则内部的 `例外` 布尔属性或 `例外条文` 自由文本字段。

## 2. 理由

1. 计划书 §4.1 已把「外部废止（后法/上位法/特别法）」列为必须表达能力。外部废止的**来源不在被废止规则内部**——它是另一条规范或另一个案件的说理。若用规则内部属性，则废止信息只能挂在被废止规则上，无法表达「A 条被 B 条废止，而 B 条自身也被 C 条限制」这种链式结构。
2. 废止条件携带时间，才能回答「2021 年的行为适用的是废止前还是废止后的规则」；内部属性无法携带时间。
3. 废止条件可携带**优先规则**，使「特别法优先」与「新法优于旧法」的冲突裁断有落点；否则冲突只能靠自然语言注释，不可校验。
4. 与「例外」区分清楚：真正的例外（同一规范内部的但书）在结构上仍是构成要件的**否定性要件**，不是废止。本决策要求：但书型例外 → 负极性构成要件；外部废止 → 废止条件。二者不得混用。

## 3. 放弃方案与代价

| 放弃方案 | 放弃原因 | 代价 |
| :--- | :--- | :--- |
| 规则内部 `例外` 属性（字符串或布尔） | 外部废止（后法/上位法/特别法）无法表达；不可携带时间；不可被查询 | 冲突裁断只能靠自然语言，SHACL 无法校验；阶段 5 的「冲突边红色」可视化失去数据基础 |
| 把废止并入「规范冲突」单一关系 | 「废止」是效力消灭，「冲突」是同时有效但结论不一致，二者法律后果不同 | 无法区分「规则已失效」与「规则有效但被排除适用」，涵摄链会误用失效规则 |

## 4. 生效约束

- 任一 `law:废止条件` 必须有 `law:废止类型`、`law:废止生效日`、`law:废止对象`。
- 若 `law:废止类型` 为 `特别法优先`，`law:优先规则` 必填（否则无从裁断，`tools/validate` 报 E-DEF-02）。
- **冲突裁断属于法律实质判断**：系统识别到废止关系但无法确定优先规则时，必须写 ESC，节点置 `pending-escalation`，不得自行选择适用顺序（§4.4 第 5 步）。
- 废止条件的成立与否不得由系统推断，只能引用权威材料或 ESC 裁定。

## 5. 复审触发条件

- 首批案例中出现「同一废止条件被反向排除」（废止的废止）→ 复审是否需要二阶废止支持。
- 若 `约定排除` 类废止占比 >30% → 复审是否将其从废止层移入「法律行为」模块（当事人意思自治），避免规范层承载过多意思表示内容。
