# ADR-0005 · 概念标识符语言

## 1. 决策

采用三元组：

| 槽位 | 属性 | 示例 | 约束 |
| :--- | :--- | :--- | :--- |
| 中文标识符（IRI 局部名） | IRI 本身 | `law:买卖合同` | 必填，唯一，不含空格/标点 |
| 中文标签 | `rdfs:label` @zh | "买卖合同" | 必填，可与标识符相同 |
| 英文注释 | `law:英文注释` | "contract of sale" | 可选，仅供外部工具与跨语言检索 |

命名空间自建：`law: = https://ontology.law-cn.internal/mcl#`（不解析，不指向任何外部站点，避免与现成法律本体命名空间冲突）。

**IRI 稳定性规则**：标识符一旦发布，只允许「废弃 + 新增」，不允许重命名（重命名会让案例层与规则层的历史引用断裂）。重命名需求一律走 CON + 别名属性 `law:曾用标识符`。

## 2. 理由

1. 计划书 §4.1 已定此方向，代价是「标识符层面引入外部法律框架」。具体而言：若用 `ContractOfSale`，则英文法律术语自带的分类预设（英美法的 offer/acceptance/consideration 三分）会隐含进入标识符，而中国法用「要约—承诺」「合同成立—生效」的不同切分。标识符是**最顽固的语义载体**：一旦写入 IRI，后续所有工具、Wiki 锚点、案例引用都固化该切分。
2. 中文标识符让法律专业人士**直接读懂 IRI**，符合 §六「人类可读、可维护」。外部盲读（§阶段 5 可选项）也因此可行。
3. 中文标识符在 RDF 1.1 Turtle 中合法（PN_LOCAL 覆盖 CJK），rdflib 7.x 已实测可解析、可 SPARQL 查询（见 `records/log/LOG-20261110-004.md` 的实测记录）。

## 3. 放弃方案与代价

| 放弃方案 | 放弃原因 | 代价（必须承认） |
| :--- | :--- | :--- |
| 英文标识符 + 中文标签（`ContractOfSale` + "买卖合同"） | 在标识符层面引入域外法律框架切分；中文法律概念（如「表见代理」「善意取得」）无稳定英文对应，翻译本身即一次解释 | 与主流工具链（Protégé、部分 SPARQL 前端、国际检索）的兼容性下降；外部工具需 UTF-8 与 Unicode IRI 支持 |
| 数字标识符 + 中文标签（`C0001`） | 人类不可读，违反 §六；接手者需查表才能理解图 | 可维护性显著下降，盲读不可行 |

## 4. 生效约束

- 概念入库前 `tools/validate` 检查：标识符非空、无空白字符、不含 `/ # ?`、在全库内唯一（E-ID-01/02）。
- 同义概念不得建两个 IRI，用 `law:同义于` 关联，并在 Wiki 标注主条目。
- 英文注释不得作为检索主键，只作辅助。

## 5. 复审触发条件

- 若引入外部工具（Protégé、图数据库导入）导致 Unicode IRI 不可用 → 复审是否增设 ASCII 别名层（`law:ascii别名`），但中文标识符仍为主键。
- 出现跨子领域复用同一概念名而含义不同 → 复审是否引入子领域前缀（`law-sale:`）。
