# ADR-0008 · 工具链与投影生成管线

## 1. 决策

| 环节 | 选型 | 理由 |
| :--- | :--- | :--- |
| 事实源载体 | RDF 1.1 Turtle，`ontology/tbox/*.ttl` 按元决策分文件 | 计划书 §阶段 3 已定「自定义 RDF 词汇表 + SHACL」。Turtle 人类可读、可 diff、支持中文标识符 |
| 概念/规则/案例实例 | 仍为 Turtle，置于 `ontology/abox/{vocabulary,rules,cases}/` | 与 tbox 同源同语法，避免同构异载体（计划书要求候选规则与成文规则同构） |
| 约束校验 | SHACL（`tools/validate/shapes.ttl`）+ `pyshacl`（RDFLib 生态） | SHACL 是 W3C 标准，非法律本体，不违反自建原则；能校验基数、必填、类归属 |
| 结构校验 | 自研 `tools/validate/validate.py`（rdflib 遍历 + 记录 front-matter 解析） | SHACL 无法表达「节点必须关联一条 open ESC」「related 必须互指」这类跨文档约束 |
| Wiki 生成 | 自研 `tools/sync/sync.py`：ontology → `wiki/`，保留 `## 维护者注记` 区块 | 满足 §六「人工补充区在重建时保留」 |
| RAG 索引 | 自研 `tools/sync/sync.py`：生成 `retrieval/manifest.json`（语义块 + 门禁标记） | 首版不引入向量库：无嵌入模型与语料，向量索引在此阶段只会引入不可验证的重量级依赖。manifest 先定义**契约**（块结构、元数据过滤维度、判断状态门禁），嵌入层可在阶段 5 前替换实现而不改契约 |
| 可视化 | 自研 `tools/vis/render.py`：生成单文件 `vis/index.html`（内联 SVG/CSS，无外部依赖） | 满足 §六 分色/虚线/红标约定；单文件可离线审阅，也便于作为交付物打开 |

所有投影**单向**：`ontology/` → 工具 → 投影。工具不得回写 `ontology/`。人工修改投影的行为由 `tools/sync` 检测（生成物内写入 `generated-by` 指纹，若指纹与内容不符则报「投影被手改」）。

## 2. 关键技术约束（已实测）

- 中文 IRI 局部名在 rdflib 7.6.0 下可解析、可查询（`law:买卖合同` 等），SPARQL 变量绑定正常。
- `pyshacl` 可用，SHACL 校验可纳入 CI 前置脚本。
- Python 3.13.14；无其他第三方依赖要求（不引入 Web 框架、不引入图数据库）。

## 3. 放弃方案与代价

| 放弃方案 | 放弃原因 | 代价 |
| :--- | :--- | :--- |
| 直接用 OWL 推理机（HermiT/ELK）做一致性检查 | 需要 Java 运行时与 OWL DL 合规建模；本项目大量使用「类作为实例属性值」的工程化写法（如 `law:归属层` 指向层个体），DL 推理会大量报错 | 只能做结构性检查（子类环、模块互斥、必填基数），不能做 DL 级可满足性推理；承认此项能力缺口并记入 RSK |
| 引入向量数据库（Chroma/FAISS）建 RAG | 当前无嵌入模型、无语料、无金标准，无法验证检索质量；引入后「manifest 契约」与实现耦合 | 首版 RAG 仅提供结构化块与门禁，语义检索留待阶段 5；检索质量的度量延后 |
| Wiki 用静态站点生成器（MkDocs 等） | 需要模板与依赖管理，且其 front-matter 约定与本项目记录体系冲突 | 需自维护少量 HTML/Markdown 生成逻辑；换取零依赖与完全可控 |

## 4. 生效约束

- 任何新工具必须放在 `tools/` 下，且必须在 `SCHEMA.md` §7 登记「输入/输出/是否可写 ontology」。
- 工具不得写 `ontology/`；唯一例外是迁移脚本，且迁移必须由 CON 授权并留 diff 记录。
- 投影文件首行写 `<!-- generated-by: tools/xxx @ <commit> -->`；人工改动投影 → 写 CHG，由工具重生成，不得直接保留改动。

## 5. 复审触发条件

- 需要做 DL 级可满足性推理 → 复审是否引入独立 OWL 推理通道（不改事实源语法）。
- 语料规模 >200 案例 → 复审 RAG 是否必须上向量层。
- 工具链总代码量 >2000 行 → 复审是否拆分独立包并引入测试框架。
