# ADR-0016 · 换行符规范化与跨平台字节一致性

## 1. 背景

`ADR-0014` 推送后，我在 `%TEMP%` 做了一次全新克隆验证，结果：

```
tbox 指纹 b3fb0e9776edf22d…  登记值 faa7773ff64001ea
[警告] W-TBOX-DRIFT  元设计指纹与登记值不一致（登记 faa7773f…，实测 b3fb0e97…）
```

本地仓库是「0 错误 0 警告」，全新克隆却是「0 错误 1 警告」。这意味着 `README.md` 宣称的
「校验 0 错误 0 警告」在外部**不可复现**——而可复现性正是本项目选择公开的核心理由（`ADR-0014 §3`）。

## 2. 根因

逐步定位，四步排除：

| 假设 | 检查 | 结论 |
| :--- | :--- | :--- |
| 提交遗漏了文件 | `git ls-tree -r origin/main \| wc -l` = 546，与本地一致 | 排除 |
| 仓库 blob 被改写 | `git cat-file -p origin/main:…` 显示 blob 全为 LF | 排除 |
| 指纹算法随机 | 读 `check_tbox_drift`：`h.update(f.read_bytes())` | 算法确定，排除 |
| **检出时换行被转换** | 逐文件比对本地 vs 克隆：6 个文件字节不同，克隆侧多出 CRLF | **成立** |

逐文件证据（本地 vs 克隆，字节数 / CRLF 数）：

```
10-module.ttl               2410 → 2456   CRLF 0 → 46
20-norm.ttl                12740 → 13039  CRLF 0 → 299
30-fact.ttl                 7455 → 7628   CRLF 0 → 173
40-case.ttl                 5241 → 5368   CRLF 0 → 127
50-application.ttl          6169 → 6313   CRLF 0 → 144
70-concept-metadata.ttl     4359 → 4441   CRLF 0 → 82
```

原因：系统级 `core.autocrlf=true`（Git for Windows 安装默认值，`git config --system` 可见）。
检出时 LF → CRLF，`read_bytes()` 读到的字节与原登记时刻不同，SHA-256 自然不同。

同时发现一个更深的问题：事实源**自身**的换行状态是混杂的——
`00-namespace` / `60-states` / `71-concepts-civil-code` 为 CRLF，其余为 LF。
这意味着原登记值不仅对 Linux 不可复现，对任何环境都只是「某个瞬间的字节快照」，而非稳定标识。

## 3. 决策

两件事，缺一不可：

1. **事实源统一为 LF**：`ontology/tbox/*.ttl` 与 `ontology/provenance/*.ttl` 全部规范化。
   涉及 4 个文件（`00` / `60` / `71` / `PROV-0001`），纯换行替换，零语义变更。
2. **新增 `.gitattributes`**：`* text=auto eol=lf`，并对 `*.ttl` `*.rq` `*.py` `*.tsv` `*.json`
   `*.md` `*.html` 显式声明 `text eol=lf`，二进制类型标 `binary`。
   锁定检出行为，使 `git checkout` 不再依赖各机器的 `core.autocrlf`。

**指纹口径不变**：仍为原始字节的 SHA-256。因为「字节即身份」这个口径是对的——
本体文件的差异确实应体现在指纹上。错的是让平台去决定字节，而不是让指纹容忍噪声。

重算后登记于 `PROV-0004`（新文件，不改 `PROV-0003`）：

| 项 | 旧值（`PROV-0003`） | 新值（`PROV-0004`） |
| :--- | :--- | :--- |
| 全量指纹 | `faa7773ff64001ea…` | `22ff6bd99c824cf5…` |
| 概念层指纹 | `6751eec0ec21afde…` | `46e380f625494f51…` |

## 4. 语义等价性证明

换行不承载 Turtle 语义（空白仅作分隔符）。机器证据：

| 指标 | 改动前 | 改动后 |
| :--- | :--- | :--- |
| 三元组数 | 8375 | 8375 |
| 类数 | 489 | 489 |
| 概念数 | 445 | 445 |
| 概念定义覆盖 | 173/452 = 38.3% | 173/452 = 38.3% |
| 校验结论 | 0 错误 0 警告 | 0 错误 0 警告 |

三元组、类、概念三项完全不变，可判定为格式性改动。按 `AGENTS.md §4.1`，这属结构性判断
（不涉及法律评价、不改变任何权利义务），故写 ADR 而不写 ESC；因未改变任何概念的内涵与外延，
**不写 CON**（见 `LOG-20261110-009` §7 说明）。

## 5. 放弃方案与代价

| 方案 | 放弃理由 |
| :--- | :--- |
| 改为「规范化换行后再哈希」（算法侧修） | 掩盖而非消除噪声：同一文件在两台机器上仍会有不同工作区字节，diff 与编辑器行为仍不一致；且会让「指纹变了 = 内容变了」这条诊断信号变钝 |
| 只在 `.gitignore`/文档里提示 `git config core.autocrlf false` | 依赖每个克隆者自觉配置。README 的「0 警告」声明必须**开箱可复现**，不能附带前置条件 |
| 保留 CRLF 作为全库标准 | 与 Git for Windows 的默认行为对抗；且 CRLF 在 Linux/CI 上会被反向转成 LF，问题换到另一侧 |
| 改登记值而不改文件（把 `b3fb0e97…` 记为基线） | 治不了根：在 Linux 克隆会得到第三个值。基线必须建立在**平台无关的字节**上 |
| 把 `W-TBOX-DRIFT` 降级为提示 | 该警告是「元设计稳定性」的唯一机器哨兵（`§阶段5` 目标为零漂移）。降低它的等级等于自毁该项门禁 |

**代价（明示）**：`PROV-0003` 的全量指纹从此不再是有效基线（其逐文件登记仍如实反映当时字节）。
这会在审计时造成「同一版本两个指纹」的观感。处置：`PROV-0004` 的注释明确写出取代关系，
`INDEX.md` 指向 `PROV-0004`，且 `PROV-0004` 记录旧值，使追溯链可闭合。

## 6. 生效约束

1. **事实源换行一律 LF**。任何编辑器若把 `.ttl` 存为 CRLF，会立即触发 `W-TBOX-DRIFT`——
   这时应修文件，不得改登记值（`ADR-0013 §5.1` 第 3 条同理：先判断样本错还是实现漏，不得改预期迁就实现）。
2. **改动 `ontology/` 后须重算指纹并新建 `PROV` 登记**，不得原地改已有 `PROV` 的指纹值
   （`PROV` 是历史凭证，不可追改；`AGENTS.md` 禁止事项 7）。
3. **`.gitattributes` 不得删除**。若确需调整，须新 ADR 并说明对指纹的影响。
4. 新增二进制类型文件时，须在 `.gitattributes` 补 `binary`，否则可能被 `text=auto` 误判。

## 7. 复审触发条件

- 若引入 CI（GitHub Actions 等），须在 workflow 中显式 `git config core.autocrlf false`，
  或在 Ubuntu runner 上验证指纹与 `PROV-0004` 一致——这是本 ADR 结论的最终检验。
- 若 `validate.py` 改为对「规范化后的内容」计算指纹（例如先 `splitlines()` 再拼接），
  本 ADR §3 的第 2 项理由需重审：届时指纹不再对换行敏感，`.gitattributes` 的作用降为工作区整洁。
- 若发现任何平台（macOS / Linux / WSL）上克隆后指纹 ≠ `22ff6bd9…`，本 ADR 应立即重开。
