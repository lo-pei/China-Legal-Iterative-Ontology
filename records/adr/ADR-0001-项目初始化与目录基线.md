# ADR-0001 · 项目初始化与目录基线

## 1. 背景与决策

工作区初始状态只有一份计划书，`INDEX.md` 不存在。按计划书 §11.1「若 INDEX.md 不存在，先创建并写 ADR-0001 说明初始化」，本 ADR 定义项目的事实源边界、目录职责与初始化偏差。

**决策**：以 `ontology/` 为唯一真值源，`wiki/`、`retrieval/`、`vis/` 全部为**生成物**（不可手改）；`records/` 为治理层（人不可直接改 `ontology/` 而不留记录）；`raw/` 为不可变输入区。

## 2. 对计划书 §三 目录树的三处补正（含理由）

计划书要求「遇到不正确或不一致的地方可自行修正并说明理由」。以下三处属结构性缺失（非法律实质判断），按 §一.6 授权自行裁定：

### 补正 1：新增 `PLAN/` 目录

§九要求产出 `PLAN/01-scope-freeze.md`，§7.1 接手读取顺序第 2 项也指向 `PLAN/01-scope-freeze.md`，但 §三 目录树中没有 `PLAN/`。若不建，则计划阶段唯一强制产物无处安放。

**处置**：建立 `PLAN/`，承载阶段级规划与冻结文档（`01-scope-freeze.md`、`02-metadesign.md`）。`PLAN/` 不承载结论性法律判断，属于规划层，与 `records/` 的治理层区分。

### 补正 2：新增 `vis/` 目录

§六要求提供概念层级图、规则依赖图、案例因子热力图、阶段健康度报告，并规定「全部由工具生成，不手改」；§6 交付物清单亦列「可视化产物」。但目录树无对应位置。

**处置**：建立 `vis/` 作为可视化**生成物**目录（由 `tools/vis` 写入）。理由：可视化是投影层，不能落进 `wiki/`（wiki 是审阅层，有人工注记区，混放会破坏「生成物 / 人工区」的边界）。

### 补正 3：明确测试集引用记录的落点

§9.1 第 2 条要求「系统为测试集每个样本建立 `testset/` 下的引用记录」，但目录树中不存在该目录，且 `raw/testset/` 依 §9.1 第 1 条为「不得修改」的不可变区。二者冲突：不可变区内不得新增系统生成的引用记录。

**处置**：引用记录改置于 `records/acc/` 之下的 `testset-refs/`（验收证据的一部分），`raw/testset/` 保持只读。理由：§9.1 第 3 条已规定「测试集上的每个判断结果不得直接进入 ontology/，结果写入 records/acc/ 作为验收证据」，引用记录与验证证据同源同址，避免第二真值源。

## 3. 考虑的替代方案与放弃代价

| 方案 | 放弃原因 | 代价 |
| :--- | :--- | :--- |
| 严格照搬目录树，不加 `PLAN/`、`vis/` | 违反 §九、§六 的强制产出要求，接手者找不到范围冻结文档 | 阶段验收缺件；后续必然临时挂载，破坏「无临时挂载」纪律 |
| 把可视化放进 `wiki/` | wiki 有 `## 维护者注记` 人工区，生成物与人工区混放会导致重建时覆盖人工内容 | 人工注记丢失风险 |
| 在 `raw/testset/` 内建引用记录 | 违反 raw 不可变约束 | 溯源链被污染，raw 与 records 的权限边界失效 |

## 4. 生效约束（后续执行必须遵守）

1. 任何 `ontology/` 变更前必须有 ADR 或 CON（§一.2）。本轮为初始化，`ontology/` 首次落地由 ADR-0006 与 ADR-0007 共同授权。
2. `wiki/`、`retrieval/`、`vis/` 只能由 `tools/sync`、`tools/vis` 写入；人工修改一律走 `records/chg/`。
3. 目录职责表见 `SCHEMA.md` §2；如与本节冲突，以本 ADR 为准并补 CHG。

## 5. 复审触发条件

- 阶段 2 结束若 `PLAN/` 内文档超过 3 份且未归档 → 复审是否需要 `PLAN/archive/`。
- 若引入外部可视化工具要求与 `vis/` 生成物目录结构冲突 → 复审。
- 若负责人要求测试集引用记录另址存放 → 以 ESC 裁定覆盖本节补正 3。
