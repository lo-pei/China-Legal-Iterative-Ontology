# ADR-0002 · 道义模态建模

## 1. 决策

在规范模块下建立独立的道义模态类 `law:道义模态`，其下三分：`law:义务`、`law:许可`、`law:禁止`。每个模态**实例**（非类）携带三个槽位：

- `law:模态条件`（该模态生效所依赖的情境条件，可指向构成要件或因子类型）
- `law:模态对象`（义务/许可/禁止所指向的行为或状态）
- `law:模态期限`（履行期、存续期、除斥期间等时间限定，可为空）

规则通过 `law:模态` 指向一个模态个体；一条规则原则上恰有一个主模态，例外情形用 `law:附属模态` 补充（如「原则允许、例外禁止」）。

**标识符**：`law:义务` / `law:许可` / `law:禁止`。不采用 `Duty`/`Right`/`Prohibition` 作为标识符（见 ADR-0005）。

## 2. 理由

1. 模态的**内部结构**需要承载。中文法律文本中「应当…在…期限内…向…支付…」把义务的主体、条件、期限、对象压缩在一个句子里；若模态只是规则的一个枚举属性值（`规范类型=义务性`），这四类信息只能散落到规则的其他槽位，导致「条件属于规则还是属于义务」无法区分，多模态规则（一条条文同时含义务与许可）无处表达。
2. 独立类使模态可被**独立引用**：防御规范常针对「某一义务是否存在」而非整条规则，模态个体可被抗辩指向。
3. 与可废止性正交：废止条件作用于规则或规范版本（ADR-0004），不作用于模态本身；若模态是属性值，这一区分无法表达。

## 3. 放弃方案与代价

| 放弃方案 | 放弃原因 | 代价（必须承认） |
| :--- | :--- | :--- |
| 模态作为规则属性值（枚举：义务性/授权性/禁止性/相对义务性） | 模态内部结构无处安放；多模态条文需拆分规则，拆分依据只能是文本句子而非规范单元 | 建模粒度上升，规则数量增加；标注者需判断「一条条文算一条规则还是数条」 |
| 把模态并入法律效果 | 效果是「规范适用后发生的法律变动」，模态是「规范对行为的评价方式」，二者在「确认之诉 + 容忍义务」类条文中会互相吞并 | 无法区分「效果包含义务」与「规范本身是义务性规范」，涵摄链末端输出含义漂移 |

## 4. 生效约束

- 任何规则节点必须且只能有一个 `law:模态`；缺失即结构不完整（`tools/validate` 报 E-RULE-05）。
- 模态个体必须至少有一个 `law:模态对象`；`law:模态条件` 可空但需在标注时说明「条件已并入构成要件」。
- 新增第四种模态（如「豁免」）须先写 CON + ADR，不得直接挂载。

## 5. 复审触发条件

- 首批 10 条规则中若 ≥3 条无法用单一主模态 + 附属模态表达 → 复审是否引入模态组合类。
- 若出现「模态冲突」（同一行为同时被许可与禁止）且无法用可废止性槽位表达 → 复审模态层与废止层的边界。
