# CON-0002 · 元数据属性分流与受控词表规范化

> 依 `ADR-0013` 执行。本次变更**不含任何法律概念**，不改变任何概念的模块归属、判断状态或溯源状态。`CON-0001` 记录的是概念层首批导入，与本条无覆盖关系。

## 1. 变更前

| 项 | 状态 |
| :--- | :--- |
| 属性类别分布 | `owl:ObjectProperty` 47、`owl:DatatypeProperty` 77、`owl:AnnotationProperty` **0** |
| 本体头 | `a owl:Ontology`；`rdfs:label`/`rdfs:comment`/`owl:versionInfo`/`law:本体版本`/`law:概念层版本`/`law:自建声明`/`law:锚定计划书条款`/`law:名称空间` |
| 版本标识 | 仅字符串 `"0.2.0-civil-code"`，无 IRI |
| 受控词表 | 裸个体（`law:状态-已验证 a law:判断状态值`），英文别名只存在于 `rdfs:comment` 的中文句内 |
| 术语归集 | 无 `rdfs:isDefinedBy`，工具无法从术语回溯到所属本体 |

## 2. 变更后

### 2.1 属性类别分流

改为 `owl:AnnotationProperty`（37 个，按文件分组）：

- `00-namespace.ttl`（14）：`锚定计划书条款`、`非法律结论`、`演练标记`、`自建声明`、`本体版本`、`名称空间`、`中文标识符`、`英文注释`、`指纹`、`覆盖范围`、`文件名`、`文件指纹`、`行数`、`有意省略domain`（新增）。
- `60-states.ttl`（11）：`标注者`、`复核者`、`标注时间`、`来源定位`、`来源文本`、`锚定能力问题`、`定义`、`示例`、`曾用标识符`、`受裁定于`、`受争议于`。
- `30-fact.ttl`（1）：`抽取者`。`40-case.ttl`（1）：`标注版本`。
- `70-concept-metadata.ttl`（10）：`概念层版本`、`概念层指纹`、`投递路径`、`投递件类型`、`规范条号`、`原清单分组`、`出现次数`、`涉及条文数`、`首次出现条号`、`清单备注`。

保持 `owl:DatatypeProperty` 的判据：字段内容是**实例的数据值**（事实文本、要件序号、生效日期、置信度、开放纹理等）。

**判据边界**：`标注者`/`复核者` 为边界个案，取注释属性的理由是它们的语义属 `SCHEMA.md` §5.3 溯源链（「这条断言来自谁」），非法律事实内容。SHACL 对其约束力不变。

### 2.2 受控词表 SKOS 骨架（增量，不动既有断言）

新增 8 个 `skos:ConceptScheme` 个体：`词表-溯源状态`、`词表-判断状态`、`词表-证成状态`、`词表-规范类型`、`词表-废止类型`、`词表-极性`、`词表-判定结论`、`词表-推理模式`。

各词表值增三类断言（`rdfs:label`/`rdfs:comment` 原样保留）：

```turtle
law:状态-已验证 a law:判断状态值, skos:Concept ;
    skos:inScheme law:词表-判断状态 ;
    skos:notation "verified" .
```

`skos:notation` 取值见 `60-states.ttl`。**`law:效果-*`（给付/形成/确认/责任）不加 notation**：英文对应在比较法上有分歧，属概念层术语选择，留待规范原文。

### 2.3 本体头

```turtle
law:本体 a owl:Ontology ;
    owl:versionIRI <https://ontology.law-cn.internal/mcl/0.2.0> ;
    owl:versionInfo "0.2.0-civil-code" ;
    vann:preferredNamespacePrefix "law" ;
    vann:preferredNamespaceUri "https://ontology.law-cn.internal/mcl#" ;
    dcterms:title "…"@zh ; dcterms:description "…"@zh ;
    dcterms:created "2026-11-10"^^xsd:date ;
    dcterms:modified "2026-11-10"^^xsd:date ;
    dcterms:language "zh-CN" .
```

原 `law:本体版本`、`law:名称空间`、`law:自建声明` 保留（既有 ADR 与 PROV 引用它们，删除会断链），标注为「保留以兼容，新写入不再使用」。

### 2.4 术语归集（评估后不采纳）

初版计划给全部 `owl:Class` / `owl:*Property` 增 `rdfs:isDefinedBy law:本体`，执行时撤回。

撤回理由：`rdfs:isDefinedBy` 的价值是「从术语回溯到所属本体」，在**多本体**场景下才有信息增量。本项目只有一个命名空间 `law:` 与一个本体，任一术语的 IRI 前缀已唯一确定其归属，该断言是重复信息。全量添加会给 489 个类与 125 个属性各增一行无差别三元组（约 614 行），稀释 diff 的可读性，而检索能力零提升。

这是「学习外部清单后判断不采纳」的一例，与 `PLAN/03` §6「不采纳项」同类。判断依据见 `PLAN/03` §3.1 与 `ADR-0013` §4。

## 5. 迁移方式

1. 手改 `00-namespace.ttl`（本体头 + 属性类别 + `有意省略domain` 声明）、`60-states.ttl`（SKOS 骨架）、其余 tbox 文件中被分流的属性声明（`10`/`20`/`30`/`40`/`50`/`70`）。
2. `71-concepts-civil-code.ttl` 不改、不重跑（§2.4 已撤回 isDefinedBy 计划），概念层指纹保持 `6751eec0…`。
3. 跑 `python tools/validate/validate.py`，须 0 错误。
4. 重跑 `tools/sync/sync.py` 与 `tools/vis/render.py`，确认投影可重生成。
5. 新增 `PROV-0003` 登记新指纹（全量 `faa7773f…` + 概念层 `6751eec0…`），`W-TBOX-DRIFT` 应消失。
6. 复核 `tbox` 行数与三元组数变化写入 `LOG`。

**回退方式**：本次为可逆改动（属性类别与新增断言均可删除），回退即从 `PROV-0002` 所列文件指纹恢复。不涉及概念内容，无需回退重标。
