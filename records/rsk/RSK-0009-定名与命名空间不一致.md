# RSK-0009 · 定名与命名空间不一致、发布前置项未完成

## 1. 风险描述

`ADR-0014` 将项目对外名称定为 CLIO 并建立公开仓库，但两类标识未同步：

1. **术语 IRI 未迁移**：`https://ontology.law-cn.internal/mcl#` 在 482 个文件、930 处引用中保留原样。
   域名含 `law-cn.internal`，与项目名 CLIO 无字面关联，且 `.internal` 为不可解析域。
2. **发布前置项缺失**：`dcterms:license` / `creator` / `publisher` 三项仍缺（`ADR-0013 §5.3`），
   `ADR-0013` 曾以「本体未发布、命名空间为 `.internal`，此时声明许可无实际后果」为不补的理由。

## 2. 影响面

- **对外可理解性**：外部读者看到项目叫 CLIO、IRI 却是 `law-cn.internal`，会追问二者关系。
  当前无文档解释，属可修复的说明缺口（`README` 已补一段，但未在 IRI 声明处就近说明）。
- **可解引用性**：`.internal` 域不可解析，任何外部方无法通过 IRI 取到定义。这在本项目自用阶段无碍，
  但一旦有外部引用即成为断链。
- **ADR-0013 §5.3 第 1 条的理由已被削弱**：原理由是「未发布故无需 license」。今日起仓库公开，
  该理由不再成立。但「公开代码仓库」与「发布本体」是两个不同事件——本仓库公开的是**构建过程与记录**，
  本体本身仍无可解析的发布地址。因此判定：**license 缺口为 medium，不阻断本次公开，但阻断「本体发布」宣称**。
- **不影响**：本地校验（0 错误）、CQ 执行、投影生成，均以本地文件为输入，与 IRI 可解析性无关。

## 3. 已采取的缓解

1. `ADR-0014 §2.3` 完整记录「为何不夹带改 IRI」的三条理由与放弃代价，避免后续接手者误判为遗漏。
2. `ADR-0014 §5` 明确冻结术语 IRI，禁止以「与新名不一致」为由单独改动。
3. `README.md` 增「命名空间」说明，交代 IRI 沿用 `mcl#` 及迁移待办。
4. 本次公开不含 `raw/authority/` 实质内容，故无「公开即泄密」风险。

## 4. 未缓解时的动作

1. **触发迁移的条件**（任一满足即须起草迁移 ADR）：
   - 首次需要对外发布可解引用本体（如 w3id、GitHub Pages + 内容协商）；
   - 任一外部方以 `mcl#` IRI 引用本项目；
   - 首次对外投稿或引用项目名（论文、报告、公开演讲）。
2. 迁移 ADR 必须同时处理四件事，缺一不得施工：`owl:priorVersion` 链、
   旧 IRI 保留期与桥接（`owl:sameAs` 或 301）、445 份投影全量重生成、
   `PROV-0003` 指纹重登记。
3. 补 `dcterms:license` 前，不得在任何位置宣称「CLIO 本体已发布」；
   可宣称的范围限于「CLIO 项目仓库公开，含元设计、校验器与治理记录」。
4. 若负责人决定维持私有或暂缓公开，本 RSK 降为 low——因 IRI 不一致在纯内部使用中不产生实际成本。
