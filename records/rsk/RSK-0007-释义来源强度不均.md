# RSK-0007 · 释义来源强度不均（12 条学理归纳不可识别）

## 1. 风险描述

投递件《民法典法律概念释义》自述：166 条释义中明示定义 70 条、规范归纳 84 条、学理归纳 12 条。但**文件未逐条标注类型**，系统无法识别哪 12 条是学理归纳。

后果：
- 概念层 445 条统一标 `溯源-投递材料` + `候选`，掩盖了内部强度差异：70 条明示定义几乎等同条文原文，12 条学理归纳则无规范依据。
- 若未来据释义起草要件文本，学理归纳条可能被当作规范表述使用，形成「二手转述冒充法条」的溯源缺陷。
- 复核时无法优先抽查风险最高的 12 条，抽样复核（门禁 3）效率下降。

## 2. 影响面

| 对象 | 影响 |
| :--- | :--- |
| `law:定义` 字段（166 条） | 12 条可能无法回指条文 |
| 阶段 3 要件文本起草 | 若引 `定义` 作要件，学理归纳条会污染要件溯源 |
| 门禁 3 抽样复核 | 无法按风险分层抽样，只能全量抽 |

不影响：`law:规范条号`（每条都有条号），可据此回到条文核对——这是当前的唯一缓解手段。

## 3. 已采取的缓解

1. 166 条全部标 `候选`，无一升 `已验证`（ADR-0012 §2.1）。
2. 每条附 `law:规范条号`，使回原文核对成为可行动作。
3. 在 `CON-0001` §2 与 `LOG-20261110-006` 中显式登记「定义未逐条比对现行文本」。
4. `law:清单备注` 保留投递人原话，未作系统改写——避免二次失真。

## 4. 未缓解时的动作

1. 阶段 3 起草第一条规则前，若仍未标注：**只允许使用 `law:规范条号` 对应的条文原文作为要件来源**，禁止直接引用 `law:定义` 文本。
2. 提请负责人于复核时在 `module-assignment.tsv` 增列标注类型（或在原投递件上补标），系统据此新增 `law:释义类型` 字段并重跑。
3. 若复核中发现释义与条文实质不符 → 写 `ESC`（不是 `RSK`），因该情形触及「概念内涵是否正确」的法律判断。
