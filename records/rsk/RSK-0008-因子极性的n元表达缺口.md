# RSK-0008 · 因子极性的 n 元表达缺口

## 1. 风险描述

`law:法律因子`（因子在某案中的出现）通过 `law:具有极性` 携带极性，SHACL 约束为 `maxCount 1`（`E-FAC-03`）。因子到构成要件的关联是**间接**的：

```
法律因子 —因子对应词表项→ 因子词表项 —锚定要件→ 构成要件
```

`law:锚定要件` 为多值（词表项可锚定多个要件）。因此存在一种结构：

- 因子实例 F 对应词表项 E；
- E 锚定要件 R1 与 R2；
- F 对 R1 是正向（支持成立），对 R2 是负向（支持不成立）。

此时 F 只能有一个极性值，**信息丢失**。这正是 W3C《Defining N-ary Relations》所述「关系带属性」的典型场景：极性的真正主体是三元组（因子 × 要件 × 极性），而非因子本身。

## 2. 影响面

| 受影响 | 说明 |
| :--- | :--- |
| 类比检索（`CQ-A01`） | 因子画像的极性比对会失真：两个案例的同一因子极性相同，但指向的要件不同 |
| 链连通校验（`E-CHAIN-01`） | 该校验只查「支撑因子锚定的要件集合是否包含关键事实填充的要件」，**不查极性方向**，故不会报错——错误是静默的 |
| 归纳（`CQ-I02`） | 候选规则从因子模式提炼时，极性方向错误会污染归纳前提 |
| 当前实际影响 | **零**。`ontology/abox/` 为空，无任何因子实例 |

**严重度定为 medium 而非 high**：缺口真实，但当前无实例、无错误输出，且一旦出现冲突会在标注阶段被人工发现（标注者会察觉「这个因子无法赋极性」）。

## 3. 已采取的缓解

1. `ADR-0013` §4 明确「不预先改造」：无实例支撑的结构重构属推测性变更，违反「不以假设为前提推进」。
2. `PLAN/03` §3.5 与 §4.5 记录该缺口与外部模式对照，使后续处理有据可依。
3. 不改 `E-FAC-03` 的 `maxCount 1`：放宽为多值会让「一个因子一个极性」的常见情形失去约束，且多值本身不能表达「哪个极性对应哪个要件」，只是把静默错误变成静默的模糊。

## 4. 未缓解时的动作

**触发条件**（任一满足即启动改造评估）：

1. 首批案例标注中出现 **≥1 例**「同一因子实例需对不同要件赋相反极性」；
2. 标注者在 `LOG` 或 `CHG` 中报告「无法为本条因子选定极性」；
3. 因子词表收敛时发现某词表项锚定 ≥2 个要件，且这些要件在首批案例中反复出现相反指向。

**处置路径**（届时）：

1. 写 `ADR` 记录重化方案（候选项：① 新建 `law:因子指向` 关系节点，携 `指向要件` + `指向极性`；② 把极性移到 `law:关键事实 —支撑因子→` 这条边上，作为限定符）；
2. 写 `CON` 记录受影响因子与画像的迁移方式；
3. 改 `shapes.ttl`（`E-FAC-03` 的 `maxCount` 与新增关系的必填）；
4. 补反例样本：构造「一个因子两个相反极性」的负例，验证新结构下不再静默通过；
5. 回测 `CQ-A01`、`CQ-I02`。

**禁止**：在 `abox` 中先按「一个因子只锚定一个要件」的约定规避，再假装缺口不存在。若采用该约定，必须写 `ADR` 明确其为**有意的表达力限制**，并在 `SCHEMA.md` §11 登记。

## 5. 复审触发

见 §4 触发条件。另：若 `ITER` 的下一轮假设检验中 `H2′`（因子词表收敛）显示词表项平均锚定要件数 >1.5，提前评估本风险。
