# RSK-0004 · 中文标识符的工具链兼容性

## 1. 实测结论（非推测）

| 环节 | 结果 | 证据 |
| :--- | :--- | :--- |
| rdflib 7.6.0 解析含中文局部名的 Turtle | 通过 | `python -c "..."` 解析 7 个 tbox 文件无报错，见 LOG-20261110-004 |
| rdflib SPARQL 查询中文 IRI（作为常量与变量绑定） | 通过 | 同上，查询返回预期绑定 |
| pyshacl 对中文 IRI 实例做 SHACL 校验 | 通过 | 演练样本校验通过 |
| Protégé / Neo4j / Jena 命令行 | **未测** | 本机无这些工具，不得声称支持 |

## 2. 风险

若交接方使用 Protégé 或图数据库直接导入，可能遇到：

- IRI 百分号编码后不可读（`%E4%B9%B0%E5%8D%96`），人类可读性优势在导入后消失。
- 部分前端按「ASCII 字母」切分 IRI 展示，出现截断。

后果不是数据损坏（IRI 仍唯一），而是**可读性优势在特定工具下退化**，影响 §六「人类可维护」与阶段 5「外部盲读」。

## 3. 缓解措施

1. ADR-0005 已预留 `law:ascii别名` 复审通道；一旦确认兼容性问题，增设只读别名层，中文标识符仍为主键。
2. `tools/sync` 生成的 Wiki 与 `vis/index.html` 全部以中文标签渲染，不显示编码后 IRI，保证审阅体验不受工具影响。
3. 交付时同时提供 `retrieval/manifest.json`，外部工具可只读该清单而不解析 RDF。

## 4. 复审触发条件

任一外部工具在导入时失败或显示乱码 → 立即复审 ADR-0005 §5 第一条，评估增设别名层。
