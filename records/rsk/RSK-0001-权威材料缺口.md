# RSK-0001 · 权威材料缺口

## 1. 风险描述

`raw/authority/` 当前为空。计划书 §阶段 2 明确「系统不得自行"发明"法律概念，遇到权威材料未覆盖的概念 → 写 ESC」。因此在本项风险未缓解前：

- 概念层（阶段 2）**零产出**，不是进度慢，而是合规产出为零。
- 规则层（阶段 3）无法建立第一条规则（§阶段 0 冷启动清单要求「构成要件 3–5 个、含至少一个开放纹理要件、至少一条司法解释作辅助规范」——这三项都必须来自权威材料）。
- 案例层（阶段 4）需要判决书原文，`raw/judgments/` 同样为空。

## 2. 影响面

| 受影响任务 | 影响方式 |
| :--- | :--- |
| 阶段 2 全部概念建设 | 阻塞（`blocking`） |
| 阶段 3 规则源文件 | 阻塞 |
| 阶段 4 因子词表与案例库 | 阻塞（词表可先立骨架，不可填实） |
| 阶段 5 回测 | 依赖测试集（见 RSK-0005） |

## 3. 当前缓解措施

1. 已把元设计（阶段 1）做到与法律内容解耦：`ontology/tbox/` 只含建模构件，不含任何法律概念断言，因此本风险不污染已有产出。
2. 已开 `ESC-0002`，明确要求首批材料的最小集合与格式。
3. 已建立 `raw/authority/README.md` 约定投递格式，负责人可直接投文件。

## 4. 未缓解时的后续动作

按 §十「僵局规则」：`blocking` 的 ESC 超时未回应则相关任务标 `blocked`，系统转做 `non-blocking` 工作（工具链、校验器、Wiki 模板、可视化、记录体系演练）。**禁止以「临时编造法条」方式推进**。
