# RSK-0002 · 复核者角色缺位

## 1. 风险描述

计划书 §5.2 门禁 3 要求「每批 ≥10% 由未参与标注者盲审」，§5.3 要求「标注者间一致性 Cohen's κ ≥ 约定阈值（双人独立标注）」，§5.1 每个标注对象的「最小必填」都含 `复核者` 字段。

若由同一执行 Agent 既标注又复核：

- `复核者` 字段写自身 → **无实质复核**，门禁 3 形同虚设，且会在记录上制造「已复核」的假象。这属于违反「记录先于实现」精神的伪记录。
- κ 无法计算（同一标注者对自己的标注一致性恒为 1），§5.3 的一致性指标不可测。
- 错误注入检出率（§5.3）需要盲审者，同样不可测。

## 2. 影响面

阶段 4 的「10 个结构完整、经专家核验」案例是阶段 5 验收的前置条件（§阶段 4 产出）。复核者缺位 ⇒ 案例不能标 `verified` ⇒ 阶段 5 测试集回测无金标准锚点。

## 3. 当前缓解措施

1. 已在标注字段设计中把 `law:标注者` 与 `law:复核者` 设为**不同**属性，并在 `tools/validate` 中加入检查：同一批内 `标注者 == 复核者` 时报警 W-SELFREVIEW（不阻断入库，但强制写入批次报告）。
2. 已开 `ESC-0003`，请负责人指定复核机制（三种选项及后果见该 ESC）。
3. 在此之前，一切标注内容只能停留 `判断状态=候选`，不得升为 `已验证`——这与门禁逻辑一致，不构成进度虚报。

## 4. 需要注意的边界

本风险不同于「法律实质不确定」。因子是否成立属法律实质判断，须走 ESC；而「谁来复核」是治理/流程问题，属结构性，可由负责人在 ESC-0003 中一次性安排，不必逐条裁定。
