# META-0001 · 自举轮机制审查

> 本文件只评价**迭代机制、升级机制、记录规约本身是否有效**，不评价本体内容质量（那是 `ACC` 的职责）。

## 1. 迭代机制

| 审视项 | 观测 | 判断 |
| :--- | :--- | :--- |
| ITER 记录成本 | `ITER-0001` 约 120 行，覆盖 6 条假设、证据、裁定、机制自审 | 成本可接受：一条 ITER 对应 5 条 LOG 的输出，比 1:1 更经济 |
| 假设颗粒度 | 6 条假设均落在「可被单一证据推翻」的粒度（如 H4 只需一次解析测试） | 合适。反例：若写成「元设计是否合理」，则无法裁定 |
| 裁定证据充分性 | 4 条证伪均有可指认的证据（ADR 写作中发现的反例、实测输出、SHACL 运行结果） | 充分。无「感觉不对」型裁定 |
| 闭环完整性 | 有输入（计划书）、有产出（tbox/工具/记录）、有机器校验、有归档 | 完整；但阶段验收缺 `ACC`，原因在 ESC |

**一处不足**：`ITER-0001` 的 H1–H3 是**事后反推**的假设（先写 ADR 才发现假设不成立）。事后反推容易把「我原本怎么想」美化成一条清晰的假设。缓解：在 `LOG-20261110-003` §2 单独记录了「初版做法 → 问题 → 修正」三列，保留真实弯路。下轮起要求假设在动手前登记（写在该轮第一条 LOG 的「本轮假设」小节）。

## 2. 升级机制

| 指标 | 本轮值 | 判断 |
| :--- | :--- | :--- |
| ESC 总数 | 3 | 与「本轮无法自行裁定的法律问题数」一致 |
| blocking 占比 | 2/3 | 合理：子领域与材料确实阻塞全部内容工作 |
| non-blocking | 1（复核者） | 合理：阻塞「升 verified」，不阻塞结构工作 |
| blocking 平均处理时长 | 0 天（当日开启，未回应） | 不可评估；14 天僵局规则尚未触发 |
| 过度升级 | 0（2 项候选被正确自行判断） | 见 `ITER-0001` §4 |
| 漏升级 | 0（逐项检查 4 个结论动作） | 唯一风险点：演练样本被误读，已三重隔离 |

**机制缺陷（重要）**：升级队列目前没有「响应时限」的机器检查。`validate.py` 只检查「open ESC 是否出现在 INDEX 队列」，不检查「开了多久」。14 天僵局规则依赖人工看日期。

处置：提出 `ADR-0011` 的一部分——校验器增加 `W-ESC-AGE`（open 超过 14 天且 blocking 时报警）。此条不阻塞当前工作，列入下轮。

## 3. 质量门禁（§5.3 指标是否真的测量）

| 指标 | 阈值 | 本轮是否测量 | 说明 |
| :--- | :--- | :--- | :--- |
| 标注 F1 | ≥0.8 | **否** | 无金标准（测试集为空，RSK-0005） |
| 溯源率 | ≥90% | **可测，本轮 100%** | 元设计断言全部有 `溯源-自建设计` + 计划书条款锚定；但这是元设计层，不是标注层。标注层溯源率待阶段 4 |
| 标注者间一致性 κ | ≥约定阈值 | **否** | 无第二标注者（RSK-0002 / ESC-0003） |
| 错误注入检出率 | ≥约定阈值 | **否** | 需盲审者 |
| 不确定升级率 | 观测而非追求低 | **是（3 条 ESC / 20 条能力问题）** | 但样本太小，不构成比率。下轮起以「ESC 数 / 判断节点数」计量 |
| 协同指标（未耦合节点数） | 应能测出 | **是** | `W-UNCOUPLED` 在演练样本上成功报出（`LOG-20261110-004` §4） |

**结论**：五项质量指标中，本轮只有「溯源率」与「协同指标」真正可测，其余三项缺**角色**或**语料**。这不是实现缺陷，是项目阶段决定的——但必须在 `ACC` 中如实标注为「不可测量」，不能记为「通过」。

**门禁 3（抽样复核）当前是形式存在**：`SCHEMA.md` §8 已把它标为「机制缺位」，但门禁清单仍列为一道门禁。建议在 `SCHEMA.md` 中把它改为「条件门禁：待 ESC-0003 裁定后启用」，避免接手者误以为已执行。

## 4. 记录规约

| 观察 | 说明 |
| :--- | :--- |
| 长期为空的记录类型 | `CON` `CHG` `ACC`。原因分别是：概念层未开工、无人类审阅、阶段未验收。已在 `INDEX.md` §5 写明「此为空缺的说明而非遗漏」 |
| 是否被反复绕过 | 无。10 份 ADR、6 份 RSK、3 份 ESC、5 份 LOG 全部独立成文，无合并、无事后补 |
| 记录成本 | 记录 md 929 行 / 建模（ttl+py）2747 行 = **0.34**。远低于 `SCHEMA.md` §10 的 1.5 阈值，未触发降级 |
| 成本口径的局限 | 用行数作代理，无法反映「写一条 ADR 花的时间 vs 写一段 ttl 花的时间」。若后续出现「记录短但极耗神」的情形，行数会低估成本。已在 `RSK-0003` 注明 |

**一处规约冲突（需修）**：`SCHEMA.md` §6 要求所有记录有 `summary` 字段，但 `ADR-0001` 之后的 ADR 均遵守，`RSK-0003` 的 `related` 却指向了当时不存在的 `META-0001`——说明「先写引用后补文件」在实践中会发生，而校验器会报 `E-REL-01`。这不是错误，是**正确的拦截**：它迫使补全。保留该行为，不放宽校验。
