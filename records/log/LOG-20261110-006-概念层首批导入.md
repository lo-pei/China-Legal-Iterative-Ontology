# LOG-20261110-006 · 概念层首批导入

## 1. 触发与输入

负责人投递两份整理件，指令「这是民法典识别到的法律概念和主体，请你加入」：

| 投递件 | 行数 | SHA-256（前 16） | 内容 |
| :--- | ---: | :--- | :--- |
| `民法典法律概念释义.md` | 357 | `5020997c080b4330` | 166 个概念，逐条「是指……」+ 条号；自述明示定义 70 / 规范归纳 84 / 学理归纳 12 |
| `民法典主体名词清单.md` | 361 | `b68f81956a24248c` | 298 个主体名词，含出现次数、涉及条文数、首次出现条号、备注 |

两件另有 `.xlsx` 版本，内容与 `.md` 同源；本批以 `.md` 为解析对象（纯文本可 diff、可哈希）。文件位于工作台目录，**未**写入 `raw/`（AGENTS §8.2 禁止系统写入 `raw/`）。

## 2. 做了什么

1. 建立导入器 `tools/import/import_civil_code.py`：解析 → 按名称合并去重 → 模块归类 → 生成 Turtle，并输出 445 行归属审阅表。
2. 新增 `ontology/tbox/70-concept-metadata.ttl`（概念层元数据词汇）与 `71-concepts-civil-code.ttl`（445 类，生成物）。
3. `60-states.ttl` 新增溯源值 `溯源-投递材料`；`00-namespace.ttl` 版本升 `0.2.0-civil-code` 并加 `law:概念层版本`。
4. `tools/validate/validate.py`：`E-MOD-01` 增加「待裁定 + 有 ESC」窄豁免；报告增加概念层指纹。
5. **修补元模型缺口**：`10-module.ttl` 增补 `law:模块 rdfs:subClassOf law:法律概念`（原缺此声明，「概念→模块→法律概念」类链断开，439 条概念会被投影与校验静默漏掉）；`validate.py` 两处排除模块类自身，避免 5 个模块被判悬浮。见 ADR-0012 §2.7。
6. `tools/sync/sync.py`：`SRC_LABEL` 增加「投递材料」；wiki 总览的「概念层为空」硬编码说明改为按实际规模生成。
7. `tools/vis/render.py`：概念按原清单分组折叠显示，新增「待裁定」区块，候选虚线与待裁定红标（此前 PLAN/02 §6 有约定但未实现）。
8. 记录与索引：`ADR-0012`、`CON-0001`、`ESC-0004`、`RSK-0007`、`PROV-0002`、本 LOG；更新 `INDEX.md`、`SCHEMA.md`、`ESC-0001` §4.1。

## 4. 关键判断（附理由，供复核）

1. **不升 `已验证`**：投递件是整理件，自述含 12 条学理归纳且未逐条标注。升格会使溯源链在首次复核时断裂（ADR-0012 §3.1，RSK-0007）。
2. **6 条不强行归模块**：`不可抗力`（客观情况）、`期间`（时间过程）、`诉讼时效`（期间/抗辩两读）、`占有`（事实控制）、`添附`（法律事实）、`善意取得`（制度/效果两读）在五模块下均无唯一自圆其说的位置，按 AGENTS §4.2 第 6 条升级为 `ESC-0004`。
3. **主体清单优先于节默认**：`业主`、`近亲属`、`家庭成员`、`遗产管理人`、`遗嘱执行人` 等在两份文件中重复出现，模块归主体，定义取释义。
4. **范围冲突显式化而非回避**：本批含 `PLAN/01` §1 排除项 33 条（人格权 11、婚姻家庭 9、继承 12、知识产权 1）。采取「概念层全量骨架 + 规则/案例层仍受 ESC-0001 约束」的双层处置，并在 ADR-0012 §5.3 写成生效约束。
5. **不建概念间类层级**：本批只落实模块归属（轴一）。`抵押权 ⊑ 担保物权` 一类包含关系需逐条判断且不影响当前检索，留待子领域确定后按需建（已登记为能力缺口）。

## 5. 未做与原因（证明不是遗漏）

| 未做 | 原因 |

| 不写 `ITER` | 本轮为内容导入执行，未提出待检验假设，不构成「假设—裁定」闭环；`ITER-0001` 的 H1′–H4′ 仍待 ESC 裁定 |

| 不写成 `abox` 实例 | 概念是类不是实例；放 abox 会使「层」轴失真（ADR-0012 §4） |
