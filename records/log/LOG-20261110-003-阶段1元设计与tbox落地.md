## 2. 本轮修正的三处自身不一致（重要，供后续参照）

| 问题 | 初版做法 | 问题所在 | 修正 |
| :--- | :--- | :--- | :--- |
| 层被建成类 | `law:规范层 a owl:Class, law:层` | 这使「层」既是个体又是类（punning）。`law:所属层` 的 range 是 `law:层`，对象必须是个体；同时 `owl:AllDisjointClasses` 又要求成员是类，两者不可兼得 | 层改为纯个体，改用 `owl:AllDifferent` 表达互异；层归属的单值性交给 SHACL `maxCount 1` 与校验器 |
| 状态值被建成类 | `law:已验证 a owl:Class, law:判断状态值` | 同上。SHACL 的 `sh:in` 与 SPARQL 的 `rdf:type` 过滤都要求状态值是**个体** | 全部状态值改为个体，并统一加语义前缀（`状态-` `证成-` `类型-` `效果-` `废止-` `极性-` `结论-` `模式-` `溯源-`） |
| 类与属性同名 | `law:构成要件` 既是类又要当属性 | Turtle 允许，但人读与校验都会混淆「这个 IRI 是类还是槽位」 | 属性改用述词命名：`具有要件` `具有效果` `归属规范类型` `隶属版本` `锚定因子` `填充要件` |

**为什么要记这一条**：这三处不是笔误，是「用类还是用个体」这个建模判断在落地时必然要过一次。记下来，阶段 2 引入真实概念时才不会重犯（尤其是「模块是类、层是个体」这条区分，新人最容易搞反）。

## 3. 为什么这样做（关键决策链）

- **先定双轴再落类**：若先写类再想轴，会出现「因子挂哪个模块」的死结。ADR-0006 把这个问题在动手前解决，代价是 ADR 写了两轮（初稿以为五模块能覆盖一切）。
- **候选规则用 `subClassOf 规则` 而非独立类**：这样「候选规则与成文规则同构」由类型系统保证，而不是靠两套手写校验。SHACL 以 `inference='rdfs'` 执行时，候选规则自动继承规则的六条必填约束。
- **元设计不加判断状态**：见 ADR-0007。若加了，第一步就卡死——元模型既不能标 `已验证`（系统自证），也不该标 `候选`（它不是候选法律结论）。

## 4. 演练结论

演练样本覆盖 9 项结构检验，全部通过：

- 4 要件（含 1 开放纹理、1 消极要件）、效果、主模态 + 附属模态；
- 主要/辅助/防御三类规范同存，防御规范与主要规范有 `冲突于` 边；
- 双版本（2000–2020 / 2020–），区间不重叠；
- 特别法优先型废止带 `优先规则`；
- 因子 → 词表项 → 要件 → 关键事实链连通；
- 类比产出的候选前提被演绎节点消费（`被演绎消费 true`）；
- 归纳产出的候选规则结构合法，因未被消费而标「未耦合」（`W-UNCOUPLED`）——这是**预期行为**，不是缺陷。

**未验证**：真实条文的语义切分（要件划几个、哪个算开放纹理）。这必须在 `raw/authority/` 到位后用真实规则重做，不能由演练替代（ITER-0001 的 H6 即此）。
