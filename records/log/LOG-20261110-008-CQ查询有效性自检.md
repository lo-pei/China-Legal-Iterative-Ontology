# LOG-20261110-008 · CQ 查询有效性自检

## 1. 本轮输入

无新指令。本轮由收尾自查触发：`LOG-20261110-007` 结项后复核「CQ 3 通过」这句结论的证据强度，发现它站不住。

按 `AGENTS.md` §6「不合并、不事后补」，本轮作为独立执行另立日志，不回填 `LOG-20261110-007`。

## 2. 缺口

`run_cq.py` 的判据是「违规查询返回 0 行」。但 0 行有两种来源：

| 来源 | 是否构成证据 |
| :--- | :--- |
| 数据确实干净 | 是 |
| 查询恒假（条件永不满足，例如属性名拼错、`FILTER` 写反） | **否** |

正常模式下二者输出完全一致，都是 `PASS 无违规`。也就是说，`LOG-20261110-007` 声称的「3 条 CQ 真的能判」只证明了查询**可执行**，没证明它**能判**。

这与 `LOG-20261110-007` §3 认定的「最严重问题是『声称可测』与『实际可执行』之间的落差」是同一个病，只是换了个位置。反例测试（`--negative`）在 `validate.py` 上堵住了这个洞，在 `run_cq.py` 上没堵。

## 3. 处置

| 项 | 内容 |
| :--- | :--- |
| 反例样本 | `tools/test/cq/bad/CQ-D02.ttl` `CQ-I02.ttl` `CQ-M03.ttl`，每个叠加一处最小构造错误，首行 `# EXPECT: <CQ>` |
| 自检模式 | `run_cq.py --selftest`：反例须令查询返回 ≥1 行；未全检出则非零退出 |
| 缺样本即失败 | 状态为 `implemented` 但无对应反例样本时，报「无可检出的证据，不得留空」并计为未检出 |
| 口径 | `SCHEMA.md` §7 增纪律 3、§8 门禁 4 改「CQ 3 条通过且自检 3/3」；`ADR-0013` §2.7 加补记（明示为事后追加，非原案） |

三个样本各自只违反一条判据，保留 1 行命中，便于区分「查询有效」与「查询过度触发」：

- `CQ-D02`：要件缺 `law:要件文本`，其余四项齐全且类型正确；
- `CQ-I02`：候选规则缺 `law:具有模态`，其余五个槽位齐全；
- `CQ-M03`：节点同时 `溯源-自建设计` 与 `状态-已验证`，即 ADR-0007 §2.4 不变式 3 所禁的「系统自证」。

## 4. 三个设计取舍

1. **反例叠加真实 tbox，不孤立加载。** 与 `--negative` 同理：孤立样本里 `law:构成要件` 不是 `owl:Class`、词表个体不存在，测出来的是「这段 turtle 能解析」，不是「本体被改坏后能发现」。这是 `LOG-20261110-007` §5.3 首轮 5/6 的教训，本轮直接沿用，未再犯。
2. **`--selftest` 不读数据集。** 自检的对象是查询，不是数据。若允许指定数据集，就会出现「换一份数据于是自检通过」的操作空间。故 `--selftest` 只吃 `bad/*.ttl` + `ontology/tbox`。
3. **缺样本按失败计，不按待办计。** 未实现的 CQ 可以标 `unimplemented`（那是范围声明）；已实现却无检出证据的 CQ 不行——那是在用范围声明掩盖证据缺失。

## 5. 校验结果

```
python tools/test/run_cq.py --selftest   → 检出率 3/3 = 100%（基础图 8375 三元组）
python tools/test/run_cq.py              → 通过 3、失败 0、空转 0、未实现 17（覆盖 3/20）
python tools/validate/validate.py        → 0 错误 0 警告
python tools/validate/validate.py --negative → 检出率 6/6 = 100%
```

未改 `ontology/` 任何文件，故 tbox 指纹与概念层指纹不变（`faa7773f…` / `6751eec0…`），不新增 `PROV`。

## 6. 口径影响

- CQ 覆盖率**仍是 3/20 = 15%**，未因自检上调。自检只证明「已实现的 3 条能判」，不证明「能判的更多」。
- 门禁 4 的措辞由「CQ 已执行 3 条通过」改为「CQ 3 条通过且自检 3/3 能检出违规」。区别在于后半句是证据，前半句只是运行记录。
- `SCHEMA.md` §7 纪律 3 为将来立规：新写一条 CQ，必须同时交一个反例；交不出反例的查询不得计入通过。这条比本轮 3 个样本本身更重要。

## 7. 未做的事

1. **未对 17 条未实现 CQ 预写查询**——理由不变（`ADR-0013` §4）：空图上写查询等于伪造可测性。自检也不能救：反例样本无从构造，因为缺的是数据模型而非查询。
2. **未给 `validate.py --negative` 增加「假阳性」检查**（即干净数据上是否误报）。当前生产态 0 警告，客观上已排除误报，但缺少针对性样本；登记于此，暂不实施。
3. **未改 `manifest.tsv` 的列结构**。反例样本路径由命名约定（`bad/<CQ>.ttl`）推出，未加列——加列会让 17 条未实现行出现空字段，与「不得留空」纪律冲突。
