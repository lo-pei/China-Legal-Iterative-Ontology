# LOG-20261110-004 · 工具链与投影管线

## 1. 做了什么

1. `tools/validate/shapes.ttl`：8 组 SHACL 形状（规则、构成要件、道义模态、文本版本、废止条件、因子、关键事实、案例、适用节点、涵摄前提、候选规则），覆盖局部基数与取值范围。
2. `tools/validate/validate.py`（705 行）：实现 SHACL 表达不了的跨节点/跨文档约束：
   - T 类层级：子类环、模块互斥、构件不得挂模块、类必须有所属层、概念不得悬浮
   - R 规范层：要件/效果/类型/证成/模态/版本齐备、同规则要件序号唯一、版本区间不重叠、废止条件四要素
   - F 事实链：因子 → 词表项 → 要件 与 关键事实 → 填充要件 的连通
   - A 适用层：候选前提最小证据、候选规则来源 ≥2、未耦合预警、链状态与节点状态一致
   - S 状态门禁：ADR-0007 §2.4 五条不变式 + 待裁定↔open ESC + 有争议↔未关闭 RSK
   - D 记录：front-matter 完整、related 互指、编号重复、孤立记录
   - X 索引：open ESC 必须在 INDEX 升级队列段、迭代谱系表存在
   - C 能力问题：概念锚定的 CQ 必须在 PLAN/01 中已定义
   - I 标识符：空白/保留字符、重名
   - P 漂移：tbox 指纹与登记值比对
3. `tools/sync/sync.py`（513 行）：ontology → `wiki/`（概念/规则/案例/决策四类页 + 总览）与 `retrieval/manifest.json`（语义块 + 元数据 + 门禁）。含：
   - **门禁单点实现** `gate()`，manifest 与 wiki 共用，避免两处漂移；`--check-gate` 用 8 个组合做自检。
   - **维护者注记保留**：重建时把 `## 维护者注记` 之后的原文接回。
   - **投影手改检测**：页面末尾写 `content-hash`，重建时若发现哈希与内容不符，报「投影被手改」并要求补 CHG。
4. `tools/vis/render.py`：生成 `vis/index.html`（单文件、无依赖、浅色主题），含规模卡、五模块分色区、构件层级树（附各类属性）、规范冲突区、门禁与图例；健康度数据由调用校验器 JSON 获得。

## 3. 修掉的三处实现错误（供后续维护者避免重犯）

| 现象 | 根因 | 修正 |
| :--- | :--- | :--- |
| 校验器把 `要件序号` 当作规则的属性去读，永远为空，`E-RULE-07` 形同虚设 | `要件序号` 的 domain 是构成要件，规则上没有该属性 | 改为遍历规则的 `具有要件`，逐个取要件序号再判唯一 |
| SHACL 报 `要件文本` 约束异常 | 误用 `sh:minInclusive`（数值比较）约束字符串 | 改为 `sh:minLength 1` |
| 校验器在 `check_cq` 上重复调用一次 | 复制粘贴残留 | 删除重复调用 |

**共性**：三处都是「写了但没跑」造成的。结论——**任何校验规则写完必须用一个会违反它的样本跑一遍**，否则无法区分「规则通过」与「规则没生效」。本轮用演练样本补上了这个缺口（例如故意让候选规则 `被演绎消费 false`，确认 `W-UNCOUPLED` 能真的报出来）。

  - 1 条 `W-UNCOUPLED`：验证「类比/归纳输出未被演绎消费」能被自动发现，正是 §一.4 要的协同指标。

门禁自检 8 个组合全部通过（`已验证+自建设计→none`、`待裁定→hint`、`无判断+非法律→meta` 等）。
