# ESC-0002 · 首批权威材料

## 1. 待裁定事项（一句话）

请确定并投递首批权威材料：拟纳入的规范原文、配套司法解释、首批判决书原文，以及是否允许系统以公开法条文本作为**临时来源**（标 `候选`）先行建模。

## 2. 系统为何无法裁定

计划书 §阶段 2 明令「系统不得自行『发明』法律概念，遇到权威材料未覆盖的概念 → 写 ESC」。ADR-0007 §2.4 亦规定 `判断状态=已验证` 必须溯源到权威材料/负责人裁定/测试集结论。

当前 `raw/authority/` 与 `raw/judgments/` 均为空。系统若自行写入法条内容，即成为「系统自证」，直接违反 §4.3 末句与 §一.6 铁律。即便系统记得条文大致内容，也存在版本、条号、修订沿革的准确性风险——**记错一个条号即造成溯源链断裂**，而溯源链是本项目的核心交付约束。

## 3. 系统已尝试

1. 已建立 `raw/authority/README.md`、`raw/judgments/README.md`，约定投递格式（文件名规范、必填元信息、只读约束）。
2. 已把 tbox 做到与法律内容完全解耦，使本 ESC 不污染已完成产出。
3. 已评估「先做结构演练」的可行性：已在 `tools/validate/fixtures/STRUCT-DRYRUN.ttl` 用显式占位标识完成元设计承载力演练，**不冒充法律内容**，因此不需要把演练样本升级为真实法条。

## 4. 阻塞什么

| 阻塞对象 | 说明 |
| :--- | :--- |
| 阶段 2 全部概念建设 | 概念的 `law:来源文本` 必填，无材料即无来源 |
| 阶段 3 规则源文件 | 构成要件、法律效果、道义模态均须由规范原文抽取 |
| 阶段 3 的 `law:规范文本版本` | 生效/公布/失效日期不得推定（ADR-0003 §4） |
| 阶段 4 首批案例 | 需判决书原文，且需文书号作溯源锚点 |

## 5. 建议裁定选项与各自后果

### 选项 A：负责人投递原件（推荐路径，非「推荐结论」）

投递内容最小集合：
1. 规范原文：目标规则的条文全文（含款项），以及其辅助规范（司法解释条文）。
2. 版本信息：公布日期、生效日期；若有修订，需给出修订前后文本。
3. 首批判决书：≥3 份，同案由、说理完整、至少 1 份含抗辩。

后果：概念与规则的溯源链完整，可直接支撑 `已验证`；工作量集中在负责人侧的材料整理，系统侧可立即开工。

### 选项 B：授权系统以公开法条文本为临时来源

后果：系统可从公开渠道取条文并标注来源 URL 与抓取时间，但所有内容只能标 `判断状态=候选` + `溯源状态=未溯源`，且必须在阶段 5 前由负责人逐条复核升级，否则不得进入确定性层。风险：条号/版本错误会在后续全链路扩散，且「候选」状态会阻塞 §4.4 推理链走到法律效果。

### 选项 C：先只做结构性交付，法律内容延后

后果：项目转入「框架先行」，交付物为元设计、校验器、投影管线、记录体系；阶段 2–4 全部标 `blocked`。优点是零返工风险，缺点是阶段 5 无法验收，且「本体」本身没有内容可审。

## 6. 裁定方式

在 `resolution` 字段写明选项（若选 A，请同时说明材料投递路径与预计时间；若选 B，请明确授权范围与是否需要逐条复核）。
