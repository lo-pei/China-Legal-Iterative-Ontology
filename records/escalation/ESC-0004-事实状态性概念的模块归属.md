# ESC-0004 · 事实状态性概念的模块归属

## 1. 待裁定事项（一句话）

`不可抗力`、`期间`、`诉讼时效`、`占有`、`添附`、`善意取得` 这 6 个概念，在 ADR-0006 的五模块（主体/行为/规范/关系/效果）下应归哪一模块——还是需要新增第六模块？

## 2. 系统为何无法裁定

五模块按「推理链功能位」划分：谁（主体）、做了什么（行为）、依据什么（规范）、谁对谁主张什么（关系）、发生什么（效果）。这 6 个概念的共同点是**它们描述的是「事实状态」或「时间过程」，而不是五个功能位中的任何一个**：

| 概念 | 释义给出的性质 | 两读及以上 |
| :--- | :--- | :--- |
| `不可抗力` | 「不能预见、不能避免且不能克服的**客观情况**」 | 事实状态 / 可作规范适用的事实前提（规范模块）/ 免责效果（效果模块） |
| `期间` | 「民事法律关系设立、变更、终止所依循的**时间过程**」 | 时间计量 / 规范适用的时间条件 / 效果发生的时间区间 |
| `诉讼时效` | 「**法定期间**；期间届满，义务人取得不履行义务的**抗辩权**」 | 期间（规范模块）/ 抗辩权发生（效果模块） |
| `占有` | 「**事实上的控制与支配**」 | 事实状态 / 物权编中的准权利地位（关系模块） |
| `添附` | 「因加工、附合、混合而使不同所有人的物结合……的**法律事实**」 | 法律事实 / 物权归属变动（关系模块）/ 取得效果（效果模块） |
| `善意取得` | 「受让人**取得**该不动产或者动产的所有权」 | 物权变动制度（关系模块）/ 取得效果（效果模块） |

按 AGENTS §4.2 第 6 条，某概念是否属于某模块「当且仅当两种归类都能自圆其说时」必须升级。这 6 条正是该情形；其余 439 条按节默认或主体清单可唯一归属，未升级。

## 3. 系统已尝试

1. 已按 ADR-0012 §2.3 的三条规则（清单主体优先 / 节默认+名称覆盖 / 待裁定）跑完全量，其余 439 条均有唯一自圆其说的归属。
2. 已排除「按定义句式归类」：`不可抗力` 的定义是「客观情况」，`添附` 的定义是「法律事实」，句式本身指向的正是「非五模块」。
3. 已确认这 6 条不被本批任何规则、要件、案例引用（本批无规则），因此待裁定不产生下游阻塞。

## 4. 阻塞什么

| 阻塞对象 | 说明 |
| :--- | :--- |
| 这 6 个概念的确定性表示 | `wiki` 中红标、`RAG` 仅作提示、不得进入任何确定性层 |
| 以 `诉讼时效`、`不可抗力` 为要件的规则 | 阶段 3 若选买卖合同价款请求权，`诉讼时效` 抗辩几乎必然出现；届时需先有归属 |
| `vis` 五模块分色的完整性 | 6 条不在任何模块分区内，另设「待裁定」区块显示 |

**不阻塞**：其余 439 条概念的检索与复核；工具链；规则层整体（本已受 ESC-0001 阻塞）。

## 5. 建议裁定选项与各自后果

### 选项 A：维持五模块，事实状态性概念统一归 `规范模块`

理由：这类概念的实际功能是「规范适用的事实前提/效力阻却」，在推理链上服务于「依据什么」。
后果：`规范模块` 由 1 条增至 7 条；概念分类的含义从「功能位」偏向「作用」。风险：`占有`、`添附` 在物权编中主要是权利变动要素，归规范模块后按模块检索会失真。

### 选项 B：维持五模块，统一归 `效果模块`

理由：`诉讼时效` 产生抗辩权、`善意取得`/`添附` 产生物权取得、`不可抗力` 产生免责，均以「发生什么」为落点。
后果：无需改元设计，改动最小；`期间` 仍勉强（期间本身不产生效果，只是效果的刻度）。风险：把「条件」与「效果」混为一谈，未来做要件—效果链时可能需二次迁移。

### 选项 C：新增第六模块「事实状态模块」

理由：五模块是「推理链功能位」，而事实状态确实不在功能位上——它是涵摄的小前提侧。承认它比塞进任一功能位更诚实。
后果：`ADR-0006` 需新增模块并声明互斥（`owl:AllDisjointClasses` 由 5 元改 6 元）；`SCHEMA.md` §4、`tools/validate` 的 `MODULE_NAMES`、`tools/sync` 与 `tools/vis` 的分色表同步修改；`vis` 增加一色。工作量约 1 轮执行，但一次到位。

### 选项 D：逐条分别归属（不统一处理）

后果：按各概念的主要功能分别归入不同模块（如 `期间`→规范、`占有`→关系、`不可抗力`→效果）。优点是无元设计改动；缺点是同类概念被拆散，且「同类不同归」本身需要在 `CON` 中逐条说明理由，后续维护成本高。

## 6. 裁定方式

在本文件 front-matter 的 `resolution` 字段填写选项与一句理由，`status` 改 `resolved`，`resolved_date` 填日期。系统据此改写 `import_civil_code.py` 的 `PENDING_REASON`（移出该表并落入对应模块），重跑导入器，更新 `CON-0001` 与 `vis`，并写 `LOG` 记录消费裁定。
