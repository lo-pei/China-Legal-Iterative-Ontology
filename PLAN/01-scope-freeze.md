# PLAN/01 · 范围冻结（草案 v0.1）

> **状态**：`draft`。子领域未定（`ESC-0001`，blocking），本文件不是生效约束。
> 裁定后由系统改写 `status: frozen`，并在 `records/acc/` 登记 P0 验收。

## 1. 项目边界

- **目标**：面向中国民事法律受控子领域，自建支持「演绎为主、类比与归纳协同」的法律推理本体，用于事实提取、法律适用、规范选择。
- **范围策略**：单一子领域深挖（ADR-0009 建议项，待裁定）。
- **子领域候选**：A 买卖合同价款请求权（建议）/ B 民间借贷利息争议 / C 负责人指定。
- **明确排除**：刑事、行政、涉外与区际法律冲突、程序法（诉讼时效作为实体抗辩事由时除外）、人格权与身份法、知识产权、公司证券。
- **不做的事**：不输出判决结论；不预测裁判结果；不替代律师意见。系统只输出**可追溯的论证结构**与**待裁定事项**。

## 2. 能力问题（按推理模式分组）

「可回测性」三档：`可回测`（系统内部检查即可验证）/ `暂不可回测`（需案例与标注积累）/ `依赖测试集`（需 `raw/testset/`）。

### 2.1 演绎（D）

| 编号 | 能力问题 | 可回测性 | 验收判据 |
| :--- | :--- | :--- | :--- |
| CQ-D01 | 给定一个请求权，能否定位其法律依据（主要规范）并列出构成要件清单？ | 可回测 | 链上节点 1 有 `请求权基础`；要件数 ≥3 且序号连续 |
| CQ-D02 | 每个要件能否携带标注（要件ID、开放纹理标记、锚定因子）？ | 可回测 | 要件必填字段齐全；开放纹理为显式布尔值 |
| CQ-D03 | 事实能否被归入要件，并给出支撑因子与推导路径？ | 暂不可回测 | 每条关键事实的 `推导路径` 可被第三方复述 |
| CQ-D04 | 涵摄链每一步能否带推理模式标签与依据？ | 可回测 | 每个适用节点有且仅有 1 个推理模式 + ≥1 个依据 |
| CQ-D05 | 防御规范（抗辩、抗辩权）能否在链上被检索并置入？ | 暂不可回测 | 含抗辩的案例中，防御规范以独立节点出现且指向被对抗的要件/规则 |
| CQ-D06 | 规范冲突（后法/上位法/特别法）能否被识别并按可废止性槽位表达？ | 暂不可回测 | 冲突以 `冲突于` + 废止条件双记录，且废止条件带生效日与优先规则 |
| CQ-D07 | 同一规范在不同文本版本下能否区分适用？ | 可回测 | 同一抽象规范下 ≥2 版本，区间不重叠，规则挂到具体版本 |

## 4. 异常处理（§十 落地）

### 4.1 回退预案（元设计被证伪时）

触发条件：阶段 2 出现「元设计无法承载某类规则」且无法在不新增顶层类的前提下解决。

迁移分档：

| 档位 | 情形 | 处置 | 需回测的能力问题 |
| :--- | :--- | :--- | :--- |
| 可批量重映射 | 仅槽位改名/上移，语义不变 | 脚本迁移 + CON 记录映射表 + 重算 tbox 指纹 | CQ-M01、CQ-M05 |
| 需局部重标 | 某类节点结构改变（如要件拆分） | 相关案例的因子画像与要件判定重标，保留旧值于 `records/con/` | CQ-D03、CQ-A01、CQ-M02 |
| 必须废弃 | 模块划分或层划分发生根本改变 | 标注作废，写 CON 说明废弃理由，重跑冷启动 | 全部 D/A/I/M |

**禁止**：在概念层打补丁（新增顶层类绕过元设计缺陷）。此类补丁一律视为元设计变更，必须走 ADR。

### 4.2 僵局规则

- `blocking` 的 ESC 超过 **14 个自然日**未回应 → 相关任务标 `blocked`，`INDEX.md` 升级队列置顶。
- 系统转做 `non-blocking` 工作；**禁止以「临时假设」「先按 A 做」方式绕过**。
- 若全部可做工作耗尽，系统输出「待裁定清单 + 每项的完成前置条件」，不产出无依据内容。

### 4.3 子领域切换判据（不临时讨论）

满足任一条即触发切换评估，且必须在阶段 4 首批 10 案例标注完成后 5 个工作日内启动：

1. 因子无法从 ≥70% 样本中可靠识别（两名标注者独立标注后，同一要件的因子集合 Jaccard 相似度中位数 <0.5）。
2. 开放纹理要件占比 >50%，导致 >30% 的要件判定只能标 `待裁定`。
3. 权威材料覆盖不足：首批规则中 >30% 的要件找不到对应的辅助规范。

切换处置：写 `ACC` 记录判据实测值 → `ADR` 记录切换决定 → `CON` 记录受影响概念 → 按 §4.1 分档迁移。

### 4.4 治理降级规则

- 阈值：阶段 2 结束时，记录撰写时间 > 实际建模时间 40% → 触发 META 审查。
- 观测口径：以文件行数为代理（记录 md 行数 / 建模 ttl+py 行数），见 RSK-0003。
- 可裁减：CHG 并入 LOG；ACC 与 META 合并为阶段报告。
- **不可裁减**：ADR、CON、ITER、ESC。

## 5. 冷启动清单（§阶段 0）

第一条规则的选定标准（全部满足）：

1. 构成要件 3–5 个；
2. 至少 1 个开放纹理要件；
3. 至少 1 条司法解释作辅助规范；
4. 至少 3 个已决案例可作来源。

第一批案例的选取标准：

1. 同案由；
2. 说理完整（对每个要件有实质论述，而非仅引条文）；
3. 因子有区分度（不同案例的因子画像不高度重合）；
4. 至少 1 案含抗辩。

第一个因子的完整标注流程（必须完整走一遍，作为流程验收）：

`raw/` 定位 → 因子识别 → 锚定要件/争点 → 极性标注 → 写 CON → 标 `候选` → 提交复核（ESC-0003 决定复核者）。

**第一周验收标准**：最小闭环走通（一条规则 + 一个因子 + 一个案例 + 一次演绎 + 一次 ESC），不追求产出数量。

## 6. 输入请求清单（供负责人安排）

| 序号 | 输入 | 最小批量 | 格式要求 | 影响的 ESC/RSK |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 子领域确认 | 1 项 | 在 ESC-0001 中勾选 A/B/C | ESC-0001、RSK-0006 |
| 2 | 规范原文 | 1 条主要规范 + 1 条辅助规范 | 纯文本或 PDF，标注公布/生效日期与条号 | ESC-0002、RSK-0001 |
| 3 | 首批判决书 | ≥3 份 | 原文（含案号），说理完整，≥1 份含抗辩 | ESC-0002、RSK-0001 |
| 4 | 复核者安排 | 1 项 | 在 ESC-0003 中选定 A/B/C | ESC-0003、RSK-0002 |
| 5 | 测试集 | 阶段 5 前 | 事实 + 规范 + 期望论证结构（非仅结论） | RSK-0005 |

### 测试集接入协议（§9.1 落地）

1. 存入 `raw/testset/`，标注版本与来源，只读。
2. 系统为每个样本在 `records/acc/testset-refs/` 建引用记录（目录归属见 ADR-0001 补正 3），标注其覆盖的能力问题编号。
3. 测试集上的判断结果**不得进入 `ontology/`**，只写 `records/acc/`。
4. 暴露的错误 → RSK 或 CON；暴露的不确定 → ESC。
5. 若据测试集调整结构，必须写 ADR 并保留「调整前/调整后」结果对照。
