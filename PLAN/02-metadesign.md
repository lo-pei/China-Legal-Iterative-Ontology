# PLAN/02 · 元设计说明（阶段 1 交付）

## 1. 设计总图

元模型 = **两条正交轴 + 三条状态轴 + 四层构件**。

```
轴一 模块（类）      主体 / 行为 / 规范 / 关系 / 效果        ← 管「法律概念」分类，互斥
轴二 层（个体）      规范层 / 事实层 / 案例层 / 适用层 / 元层  ← 管「建模构件」归层，单值
状态三轴             溯源状态 / 判断状态 / 证成状态            ← 管「可信度」与「不确定性」
```

**为什么必须分两条轴**：若强行把「因子」挂进五模块，标注者要回答「『及时提出异议』是行为还是关系」——这是无意义且不可校验的判断，且会让分类分歧伪装成法律分歧。构件的层归属是可判定的，概念的模块归属才是法律判断。详见 ADR-0006 §3。

## 2. 五模块的落地形式

模块建为 `owl:Class`，声明 `owl:AllDisjointClasses`；法律概念类以 `rdfs:subClassOf` 挂到**恰好一个**模块。

| 模块 | 承载 | 典型概念（阶段 2 由权威材料引入，此处仅示例方向，不作为内容） |
| :--- | :--- | :--- |
| 主体模块 | 谁 | 自然人、法人、非法人组织、行为能力、代理 |
| 行为模块 | 做了什么 | 法律行为、意思表示、履行、违约行为 |
| 规范模块 | 依据什么 | 规范类型、解释、效力 |
| 关系模块 | 谁对谁主张什么 | 合同关系、请求权、抗辩权 |
| 效果模块 | 发生什么 | 给付、形成、确认、责任 |

**校验**：`E-MOD-01`（无模块归属=悬浮）、`E-TAX-02`（多模块归属=冲突）、`E-TAX-01`（子类环）。

## 3. 四元决策的落地形式

| 元决策 | 落地类/属性 | ADR | 关键校验 |
| :--- | :--- | :--- | :--- |
| 道义模态独立类 | `law:道义模态` ⊃ `义务`/`许可`/`禁止`；槽位 `模态条件` `模态对象` `模态期限`；规则 `具有模态`（1）+`具有附属模态`（n） | ADR-0002 | 规则必须恰有 1 主模态（E-RULE-05）；模态必须有对象 |
| 时间性双层 | `law:抽象规范` —`具有版本`→ `law:规范文本版本`（公布/生效/失效日期、文本定位）；规则 `隶属版本`（1） | ADR-0003 | 版本必须有效日期（E-VER-03）；同规范版本区间不重叠（E-VER-02） |
| 可废止性独立槽 | `law:废止条件`（六类废止类型、生效日、优先规则、理由定位）；`废止对象`、`受废止于` | ADR-0004 | 特别法优先必填优先规则（E-DEF-02）；废止生效日必填（E-DEF-05） |
| 中文标识符 | IRI 局部名为中文；`中文标识符` `英文注释`；命名空间自建 | ADR-0005 | 标识符不得含空白/保留字符（E-ID-01）；不得重复（E-ID-02）；不得改名，只能废弃+新增 |

**但书型例外 vs 废止的硬边界**（ADR-0004 §2.4）：
- 规范内部的但书 → 建为 `消极要件 true` 的构成要件；
- 外部效力消灭（后法/上位法/特别法） → 建为 `废止条件`。
二者不可混用。混用会使「规则是否还存在」与「规则是否适用」不可区分。

## 4. 构件清单（tbox 落地结果）

| 层 | 构件类 | 关键属性 |
| :--- | :--- | :--- |
| 规范层 | 规则、构成要件、法律效果、道义模态（义务/许可/禁止）、抽象规范、规范文本版本、废止条件 | 具有要件、具有效果、归属规范类型、证成状态、隶属版本、具有模态、要件序号、开放纹理、消极要件、锚定因子、归属废止类型、废止生效日、优先规则 |
| 事实层 | 生活事实、因子词表项、法律因子、关键事实 | 事实文本/来源/时间/置信度、因子编号、锚定要件、锚定争点、因子对应词表项、具有极性、证据定位、填充要件、支撑因子、推导路径 |
| 案例层 | 案例、因子画像、要件判定、深层关联、争点 | 文书号、具有因子画像、画像含因子、判定要件、判定结论、依据因子、说理摘录、关联争点、涉及原则/政策、标注版本 |
| 适用层 | 推理链、适用节点、涵摄前提、候选规则 | 起源请求、请求权基础、链状态、属于链、节点序号、具有推理模式、依据/产出、来源先例、类比相似点/差异点、来源案例集、反例、被演绎消费、消费于 |

**候选规则与成文规则同构**：`law:候选规则 rdfs:subClassOf law:规则`，因此自动继承规则的全部必填约束（SHACL 以 `inference='rdfs'` 执行，无需重复写形状）。差异只在 `证成状态=待检验`。

## 5. 状态三轴（ADR-0007）

```
溯源状态（来源）   权威材料 / 负责人裁定 / 测试集结论 / 自建设计 / 未溯源
判断状态（认识）   已验证 / 候选 / 待裁定 / 有争议 / 已否定
证成状态（规则）   已确立 / 待检验
```

三条硬约束：
1. 系统不得把自己算出来的东西标 `已验证`（E-PROV-01）。
2. 待裁定必有 open ESC（E-ESC-01）。
3. 元设计断言不带判断状态，带 `非法律结论 true`（ADR-0007 §2.2）。

## 6. 可视化约定（§六 落地）

由 `tools/vis/render.py` 生成单文件 `vis/index.html`，规则固定如下：

| 视觉元素 | 语义 |
| :--- | :--- |
| 分色 | 五模块各一色（主体=靛蓝、行为=青、规范=紫、关系=绿、效果=橙） |
| 虚线边框 | `判断状态=候选` |
| 红色徽标 + 红边 | `判断状态=待裁定` |
| 灰色删除线 | `判断状态=已否定` |
| 无模块色（仅描边） | 构件类（规则/因子/案例等），不参与模块分色 |
| 红色连线 | 规范冲突（`冲突于`） |
| 无「维护者注记」入口 | 可视化只读，修改走 CHG |

**生成物纪律**：文件首行写 `generated-by` 指纹；人改即视为投影污染，重生成并回写 CHG。

## 7. 结构演练结论（阶段 1 验收项）

计划书要求「用一条真实民事规则（含例外 + 抗辩）手工形式化」。真实规则须来自 `raw/authority/`（当前为空，ESC-0002），故以**显式占位样本**完成同一结构检验：`tools/validate/fixtures/STRUCT-DRYRUN.ttl`。

演练覆盖项与结果：

| 检验项 | 样本中的承载 | 结果 |
| :--- | :--- | :--- |
| 构成要件 4 个，含开放纹理 | 要件 1/2/3（开放纹理）/4（消极要件） | 通过 |
| 主模态 + 附属模态 | 防御规范 R-C：禁止（主）+ 许可（附属） | 通过 |
| 主要/辅助/防御三类型同存 | R-A / R-B / R-C | 通过 |
| 文本版本双层（含失效） | v1 2000–2020，v2 2020– | 通过，区间无重叠 |
| 外部废止（特别法优先） | 废止条件带优先规则 | 通过 |
| 因子 → 词表项 → 要件 → 关键事实 | F-9001/F-9002 链 | 通过，链连通 |
| 类比产出被演绎消费 | 前提 1 → 节点 3 | 通过（`被演绎消费 true`） |
| 归纳输出 | 候选规则（来源 2 案例） | 通过结构，标 `未耦合`（`被演绎消费 false`），触发 W-UNCOUPLED |
| 待裁定 → ESC | 样本用 `受裁定于 ESC-0002` 占位 | 通过 |

**结论**：元设计**无矛盾承载**上述结构，不需要在概念层打补丁。**未验证部分**：真实条文的语义切分（要件划分数目、开放纹理的认定）无法由演练替代，须待 `raw/authority/` 到位后重做一次真实规则形式化，并写入 `ACC`。
