## 硬性要求

1. **「本院认为」必须完整**：因子识别与要件判定的证据全部来自此节。若只给结论段，系统无法标注因子，只能对结论做二次推断——那是推测，不是标注。
2. **款项与数额不得省略**：因子常由数额、日期、比例构成（「已付 60%」「逾期 30 日」），删掉即无法判极性。
3. **程序性内容可略**：送达、管辖异议等与要件无关的部分可删除，但须在 `全文完整性` 中注明。
4. **一案一文件**：不得把多案合并；不得只给摘要。

## 首批选案标准（对应 PLAN/01 §5）

| 条件 | 说明 |
| :--- | :--- |
| 同案由 | 便于因子词表收敛 |
| 说理完整 | 对每个要件有实质论述，而非仅引条文 |
| 因子有区分度 | 不同案例的因子画像不高度重合 |
| ≥1 案含抗辩 | 用于检验防御规范能否在链上被置入（CQ-D05） |

## 系统会做什么

1. 抽取生活事实（原子陈述），建 `law:生活事实`。
2. 识别法律因子，标极性、锚定要件/争点、记录证据定位与标注者。
3. 建关键事实（要件判定结论）与推导路径，标 `判断状态=候选`。
4. 因子若不在现有词表内 → 提候选词表项（需锚定要件或争点，否则为悬浮，禁止入库）。
5. 任何「该因子是否成立」「极性为正还是负」的判断，若缺乏权威依据 → 写 ESC，不自行判定。
