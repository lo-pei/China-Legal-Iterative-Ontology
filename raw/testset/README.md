# raw/testset/ · 测试集投递说明（只读区）

> 计划书 §二.1：测试集「阶段 5 前提供」。接入协议见 `PLAN/01-scope-freeze.md` §6 与计划书 §9.1。

## 一、测试集要测什么（决定它该长什么样）

本项目的验收不是「结论对不对」，而是**论证可不可追溯**（§阶段 5）。因此测试集样本需要给出：

1. 事实（可原子化的事件陈述）；
2. 可用规范（条文，含版本）；
3. **期望的论证结构**：哪些要件应被识别、哪些因子支撑、哪一步会触发类比、哪一步应停下并升级。

若只给「事实 + 判决结果」，则只能测结论一致性，无法测推理链完整性——那与本项目目标不符。

## 二、文件格式

```
TESTSET-YYYYMMDD-NNN-说明.md
```

```markdown
---
测试集版本: 1.0
来源: 负责人提供 | 公开案例整理
样本数: 20
---

## 样本 S-001

- 案由: ...
- 事实: （原子陈述，每条一行）
- 可用规范: AUTH-xxx 第 X 条
- 期望要件数: 4
- 期望触发类比: 是（要件 3 为开放纹理）
- 期望升级: 否 | 是（说明哪一步无法裁定）
- 期望结论类型: 支持 / 不支持 / 部分支持（仅作参考，不作评分主项）
```

## 三、接入纪律（§9.1）

1. 存入本目录后**只读**，标注版本与来源，不得修改。
2. 系统为每个样本在 `records/acc/testset-refs/` 建引用记录（目录归属见 ADR-0001 补正 3），标注其覆盖的能力问题编号（CQ-xxx）。
3. **测试集上的判断结果不得进入 `ontology/`**，只写 `records/acc/` 作为验收证据。
4. 暴露的系统错误 → `RSK` 或 `CON`；暴露的系统不确定 → `ESC`。
5. 若据测试集调整结构，必须写 `ADR` 说明理由，并保留「调整前 / 调整后」结果对照。测试集不用于调参式迭代。
